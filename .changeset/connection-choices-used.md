**A call uses the company connection its run's mailbox or its agent's choice names, and runs only on the connection it was approved against.** For a company need, a resolver now takes, in order: the company connection the run's mailbox reads with, when the mailbox is the company's, of the need's app, and names one; else the connection the call's agent or flow chose for the app in the project, in this environment; else the only candidate (a live company connection of the app, working or needing a reconnect, on a registration that allows the project, in this environment). No candidate is `connection-missing`, as before. Several, and no choice of one, is the new `connection-not-chosen`, listing them by name: the turn fails, rather than pick one or ask the model to, and the API answers `409 connection-not-chosen` when the call waits for the run, with `details.connection` and `details.choices`. A connection the mailbox or a choice names that can't serve the call (disconnected, in another environment, on a registration that no longer allows the project, lacking a permission, or needing a reconnect) is `connection-missing`, naming it, and never falls back to another. An id that isn't one of the company's connections of the app answers as no connection does. Candidates are counted before permissions, so of two where only one holds what the call needs, neither is picked silently. A person's own connection is found as before.

- `@kindgi/tools`: `ResolveConnectionsInput` gains `target` (the call's agent or flow, which a runtime checks against the run's own record) and `mailbox` (`ConnectionRunMailbox`, the run's mailbox as the run records it). A refusal can be `connection-not-chosen`, with `choices` (each candidate's `connectionId` and `name`). `ToolConnection` gains `name`: the connection's label, else its account's.
- `@kindgi/runtime`: `RunMailbox` gains `connectionId`, the company connection the fire read the mail with: the one the trigger names, else the only one it read with, written once at the fire. A run from before connections had names carries none.
- `@kindgi/connections-inmemory`: resolves a company need in that order, and gives each token its connection's `name`.
- `@kindgi/agents`: the connection gate asks with the call's agent and the run's mailbox. `connection-not-chosen` fails the turn (`ConnectionNotChosenError`, with the tool's name for the connection and the choices' names), whether at the first ask, after a connect, or on the fresh ask right before the tool runs; the model never reads it. A call whose fresh ask comes to another connection than the gate decided on, a person's or the company's, runs nothing and fails with the new call code `connection-changed`, naming both, which the model reads like the other connection codes; so does the ask after the app refused a token. An approval for a call that uses a company connection and no person's now shows that connection (`HitlEnqueueInput.connection`), with no `approver`: the reviewers decide it as before. `connection` gains `name`.
- `@kindgi/api`, `@kindgi/client`: `ApprovalConnection`, on an approval and in a run's `waitingFor`, is set for a company connection too, and carries the connection's `name`. The errors reference has `connection-not-chosen`.
