A build's signed envelope can say what it was built from: `builtFrom: { kind: 'kept-repo', projectId, commit, requestedBy }`, a commit of a repository the runtime keeps for a project without a GitHub repository, and who asked for the build (`user:` and their id). `POST /v1/deployments` takes the field, the signature covers it with its keys sorted, and the deployment keeps it; a promotion keeps it and checks the signature over it again. A field in it the runtime doesn't know, another kind, a project id that isn't a lower-case UUID, a commit that isn't a full lower-case hex id, or a `requestedBy` that isn't `user:` and an id is `400`. An envelope without the field signs the same bytes as before, and a build carrying it deploys only on a runtime that knows it, since an earlier runtime checks the signature without it. Each new deployment, not a repeat of one the runtime has, is recorded in the audit trail as `deployment-registered`: who registered it and, when its envelope says, what it was built from.
