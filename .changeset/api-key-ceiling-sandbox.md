An API key can now be minted with a `ceiling`. The one ceiling so far, `sandbox`, holds the key to what a plain project editor holds in the key's project, whatever its principal or role may do: read, write, call, execute and cancel where an editor holds them there, only reads on the workspace, its orgs and teams, and nothing else. A key with a ceiling takes no admin action, mints, lists and revokes no keys (`403 key-ceiling-refused` on every keys route), registers, changes and runs-now no schedule, event, mail or webhook trigger (it reads them), decides no approval (it carries no reviewer role, and its person's reviewer seat doesn't count), opens no console session (`403 token-sign-in-not-allowed`), reaches no route that acts for its person in every project (sessions, second factor, connection changes), and carries no capabilities. A run the key starts (`call`, `execute`) runs as the key's person, like any of their runs: its tool and MCP calls use their grants, or the agent's, not the ceiling. Such a run is marked: the run's `keyCeiling` is `sandbox` on its read and in the run list (`startedBy` stays `person`), set from the caller's key and never from the body; `@kindgi/runtime` adds `RunKeyCeiling` and `RUN_KEY_CEILINGS`, and the run start inputs and the run record (`@kindgi/runtime`, `@kindgi/agents`) carry `keyCeiling`. If a revoke after `key-ceiling-not-kept` fails, a warn line names the key's id so it can be revoked by hand. The mint takes `ceiling` only with a `projectId`, the `member` role or none, and no capabilities (`bad-input` otherwise). A runtime that runs without authorization can't hold a key to a ceiling: it refuses the mint and every request from such a key (`501 key-ceiling-unsupported`). If the key store doesn't keep the ceiling, the mint revokes the new key and answers `500 key-ceiling-not-kept`. A key's `ceiling` shows in the key list and get, whoami and `GET /v1/identity/me/permissions`, whose project role for such a key is `editor` at most and whose capabilities hold only what the ceiling keeps. `@kindgi/authz` adds `PROJECT_EDITOR_ACTIONS`, what a plain project editor holds on each object type. The Python (`kindgi`) and JVM (`kindgi-models`, `kindgi-client`) clients take and show `ceiling`, and a run's `keyCeiling`, the same way.
