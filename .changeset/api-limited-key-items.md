On a runtime without an authorization store, a key or session limited to a project is refused, `403 key-project-mismatch` (`details.keyProjectId`, `details.projectId`), a change by an item's id that reaches another project the item is in or runs in, as a store would refuse it: unregistering or reinstating a version of an agent, flow, tool, block or test set; pinning or unpinning an agent, flow or tool; taking an agent over; adding or retiring an agent's test case; unregistering a guardrail or an MCP endpoint, or running an MCP endpoint's prompt; changing or unregistering a corrector group; and registering or changing an event trigger whose flow is in another project. Unregistering an MCP endpoint of the workspace's or an org's, and changing or unregistering a workspace corrector group, are refused the same way, without `details.projectId`. An item in more than one project is refused only where the change reaches beyond the key's project, and the message says the item runs in that project too. Items in the key's own project, items in no project, ids the runtime doesn't find, and reads pass as before. A runtime with a store is unchanged and still answers `permission-denied`.
