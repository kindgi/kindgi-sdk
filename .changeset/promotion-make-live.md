**Making a promotion's carried agents live in the target, and refusing a live change that would span an environment order.**
- `POST /v1/deployments/{deploymentId}/promotions` takes `makeLive?: boolean`. With `makeLive: true`, once the build has moved, every agent version the promotion carried is pinned live in the target project, each through its scope's gate — the same path a live route takes. The answer gains `live`: one `{ id, version, pinned, gate? }` per carried agent. `pinned: true` is live now; `pinned: false` carries `gate` (its `status`, `promotionId`, the `policy` that applied, an `approvalId`, and the `checks`) for one waiting on an approval or refused by a check. `live` is present only when `makeLive` was asked. Re-running is safe: the move is idempotent, and a pin already in place passes. Making the carried agents live needs admin on the target project; when the caller lacks it the promotion still answers (the move committed), and the make-live is the `403` — fix the grant and promote again.
- `kindgi promote --make-live` asks for it, and prints each agent made live in `--to`, with any waiting on a gate. `--json` carries `live` on the promotion.
- New error code `409 live-scope-spans-environments`: for an agent that runs in more than one project of an environment order, a change to what's live at a scope wider than one project — the tenant's, or an org's — would span the order's environments, and is refused. It is answered after the authorization check (so an unauthorized wide change is still the `403`), on `POST /v1/agents/{agentId}/promotions`, `POST /v1/agents/{agentId}/live/rollback`, and a proposal's `request` and `rollback`. Pin a project, or a segment of it, instead. An unpin at any scope, and every change for an agent one project serves, are unaffected. A deployment's make-live pins one project, so it never meets this refusal.
- `@kindgi/api`: `DeploymentsRouterBindings` gains optional `agentReleases`, `releaseGateDeps` and `itemRights`, which `createApp` now wires; a composition that mounts `deploymentsRouter` itself supplies them for `makeLive` (absent, `makeLive` answers `501`). `liveChangeRefusal` takes `setsLive` and folds in the width check; `widthRefusal` is exported for the routes that run it after their own authorization.
- `@kindgi/client`: `makeLive` on `deployments.promote`, and `live` on the promotion it answers.
