A Python pack's image build now fails when one of the pack's modules won't import there, instead of leaving that module's tools out of the image's index. Before, the build went on, and `kindgi build` then stopped at the integrity gate, which said only that the image's index differed from the local one. The image installs the main dependencies only (`uv sync --no-dev`, or Poetry's main group), so a package that a tool imports and only a dev group lists loads under `kindgi dev` but not in the image. The build log now names the file and the missing module, and says to move the package to `[project].dependencies` (in a Poetry 1 app, `[tool.poetry.dependencies]`). A helper module whose name starts with `_` that won't import there doesn't stop the build: nothing in the index needs it, and a tool that imports it fails on its own. The image runs the pack's own `kindgi`, so this needs a `kindgi` whose `python -m kindgi.pack index` has `--strict`. With an older one, the image indexes as before.
