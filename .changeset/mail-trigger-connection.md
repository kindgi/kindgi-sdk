**A mail trigger on the company's mailbox names the company connection it reads with.** `config.mailbox` gains `connectionId`, only with `as: company`: one of the project's company connections of the app, as `GET /v1/connection-choices/candidates` lists them. With none named, a register (`POST /v1/mail-triggers`) or an update (`PATCH /v1/mail-triggers/{triggerId}`) that puts the trigger on the company's mailbox stores the project's only one, so a connection added later doesn't change what it reads; with none, nothing is stored; with several, it's `409 connection-not-chosen`, with `details.choices` (each one's `connectionId` and `name`, sorted by name) and `details.field` `config.mailbox.connectionId`, and nothing changes. A named id that isn't one of the project's candidates is `404 connection-not-found`, the same answer as for an id that doesn't exist, with `details.field`. A `connectionId` on a person's mailbox, or one naming a person's connection, is `400 bad-input`: a person's mailbox is read with its owner's own connection. Pointing a trigger at another connection, or naming one where it named none, is a change of mailbox, as another app is: it takes a project admin, a `toolsAllowedUnattended` list must be named again, the folder goes back to the inbox unless one is named, and an audited change lists the mailbox before and after. A move to a person's mailbox drops the id. The trigger's answers carry `connectionId` when it names one.

- `@kindgi/runtime`: `MailTriggerMailbox` gains `connectionId`. The trigger registry stores it as given: a stored id is the connection the poller reads with. A trigger that names none while the project has several has the status reason `connection-not-chosen`, which names them, and doesn't poll until it names one. A fire records the id of the connection its read opened in the run's `mailbox.connectionId`.
- `@kindgi/api`: the mail triggers router takes the server's connection binding and environment (`connections`), and decides the connection from it. With no project to check against, a named id must be the tenant's live company connection of the app in this environment. A server without a connection binding answers a named id `404 connection-not-found` and stores none. The in-memory trigger registry treats another `connectionId` as another mailbox. The errors reference widens `connection-not-chosen` to a mail trigger's register and update.
- `@kindgi/client`: `MailTriggerMailbox` has `connectionId`. A `409 connection-not-chosen` comes as a `conflict` whose `reason` is `connection-not-chosen`, with `fields.choices` and `fields.field`.
