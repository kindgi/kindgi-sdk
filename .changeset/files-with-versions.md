**Files with versions.** A runtime that keeps files serves `/v1/files`: a file is a name and its versions 1, 2, 3, each one stored blob, read by its number or by `latest`. The operations are `files.list`, `files.create`, `files.get`, `files.delete`, `files.versions.list`, `files.versions.add`, `files.versions.get`, `files.versions.download` (the bytes, with `X-Kindgi-File-Version`), `files.versions.restore`, `files.versions.delete`, `files.versions.pin`, `files.versions.unpin` and `files.pinHistory`. Adding or restoring a version takes an optional `expectedVersion`: when Latest isn't that version, nothing is written and the answer is `409 file-version-conflict`. Bytes that are Latest's add no version (`200`, `created: false`). A restore is a new version with an earlier version's bytes, type and tags, under Latest's name. A pinned version can't be deleted, nor a file with one (`409 file-version-pinned`), and a file's last live version goes only with the file (`409 file-last-version`). Reads need `read` on the file's project, or `run` there for a file of the caller's own; changes need `write`. An upload has the artifact upload's cap: over it is `413 file-too-large`.

`createApp` takes the store as `fileVersions`, a `FileVersionsBinding` from `@kindgi/blob-binding` (its types are also exported by `@kindgi/api`); without one, `/v1/files` isn't mounted. A file's id is its version 1's `blobId`. `BlobMeta` gains `fileId` and `version`, for a blob that is a file's version, and `/v1/artifacts` answers carry them; deleting an artifact whose bytes a file still needs is `409 artifact-in-file`. `FileValue` in `@kindgi/types` takes `fileId` and `version`, both or neither, and `FileId` is a new id type. The retention domains gain `file_version`, opt-in like `memory` and `conversation`: a deleted version goes after the grace, and so does one that isn't Latest, isn't among its file's newest 10, isn't pinned, and was superseded longer ago than the grace. The error codes `file-not-found`, `file-version-not-found`, `file-version-conflict`, `file-version-pinned`, `file-last-version`, `file-too-large` and `artifact-in-file` are in the API's status map and the error codes reference, and the TypeScript client reads each as its kind.
