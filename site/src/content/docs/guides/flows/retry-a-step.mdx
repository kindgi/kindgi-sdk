This guide retries a flow step that fails now and then, with backoff, and
gives it a time limit.

A step that calls something flaky can be retried before its failure fails the
run. The retry policy goes on the **edge into the step**.

## Before you start

- **A pack on a runtime such as `kindgi dev`,** with Kindgi 0.2's CLI.
- **A step that's safe to run twice,** as the caution in
  [The policy](#the-policy) explains.

## Retry a step

Ask your coding agent: "I want a flow that reserves an order's stock at the
warehouse, and tries again while the warehouse is busy." Kindgi's skills in
your pack tell it how ([How it knows Kindgi](../../../start/coding-agents/)).
For reference, the tool and the flow look like this. `acme.reserve-stock`
calls a warehouse that is busy for the first two calls per order, and the
flow's edge into the step retries it:

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts
// tools/reserve-stock/index.ts
import { defineTool } from '@kindgi/sdk/define';
import type { ToolId } from '@kindgi/sdk/types';
import { z } from 'zod';

// The warehouse API is busy for the first two calls per order.
const calls = new Map<string, number>();

const defined = defineTool({
  id: 'acme.reserve-stock' as ToolId,
  description: 'Reserves the stock for an order at the warehouse.',
  version: '0.1.0',
  input: z.object({ orderId: z.string() }),
  output: z.object({ orderId: z.string(), reserved: z.boolean(), attempt: z.number().int() }),
  effects: [],
  handler: async ({ orderId }) => {
    const attempt = (calls.get(orderId) ?? 0) + 1;
    calls.set(orderId, attempt);
    if (attempt < 3) throw new Error('Warehouse busy (503)');
    return { orderId, reserved: true, attempt };
  },
});

if (defined.kind === 'err') throw new Error(defined.error.message);

export default defined.value;
```

```ts
// flows/reserve-order/index.ts
import { defineFlow } from '@kindgi/sdk/define';

const defined = defineFlow({
  id: 'acme.reserve-order',
```

```python
# tools/reserve_stock.py
from pydantic import BaseModel, Field

from kindgi import tool

# The warehouse API is busy for the first two calls per order.
calls: dict[str, int] = {}


class ReserveInput(BaseModel):
    order_id: str = Field(alias="orderId")


class Reserved(BaseModel):
    order_id: str = Field(alias="orderId")
    reserved: bool
    attempt: int


@tool(id="acme.reserve-stock")
def reserve_stock(input: ReserveInput) -> Reserved:
    """Reserves the stock for an order at the warehouse."""
    attempt = calls.get(input.order_id, 0) + 1
    calls[input.order_id] = attempt
    if attempt < 3:
        raise RuntimeError("Warehouse busy (503)")
    return Reserved(orderId=input.order_id, reserved=True, attempt=attempt)
```

```java
// src/main/java/acme/tools/ReserveStock.java
package acme.tools;

import com.kindgi.pack.Tool;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

public final class ReserveStock {
  public record Input(String orderId) {}

  public record Output(String orderId, boolean reserved, int attempt) {}

  // The warehouse API is busy for the first two calls per order.
  private static final Map<String, Integer> CALLS = new ConcurrentHashMap<>();

  public static final Tool<Input, Output> TOOL = Tool.define("acme.reserve-stock")
      .description("Reserves the stock for an order at the warehouse.")
      .version("0.1.0")
      .input(Input.class)
      .output(Output.class)
      .handler((input, ctx) -> {
        int attempt = CALLS.merge(input.orderId(), 1, Integer::sum);
        if (attempt < 3) throw new IllegalStateException("Warehouse busy (503)");
        return new Output(input.orderId(), true, attempt);
      });

  private ReserveStock() {}
}
```

```scala
import java.util.concurrent.ConcurrentHashMap

object ReserveStock {
  final case class Input(orderId: String)
  final case class Output(orderId: String, reserved: Boolean, attempt: Int)

  // The warehouse API is busy for the first two calls per order.
  private val calls = new ConcurrentHashMap[String, Integer]()

  val tool: Tool[Input, Output] = Tool[Input, Output]("acme.reserve-stock")
    .description("Reserves the stock for an order at the warehouse.")
    .version("0.1.0")
    .handler { (in, _) =>
      val attempt: Int = calls.merge(in.orderId, 1, (a, b) => a + b)
      if (attempt < 3) throw new IllegalStateException("Warehouse busy (503)")
      Output(in.orderId, reserved = true, attempt)
    }
}
```

`--flow` is the flow, and `--input` its input. It prints the run, which
completed at the third attempt:

```json
{
  …
  "status": "completed",
  …
  "output": {
    "attempt": 3,
    "orderId": "A-200",
    "reserved": true
  },
  …
}
```

The journal, which `kindgi runs journal <run-id>` prints, has each retry. It
shows the error that caused it and the wait before the next attempt:

```json
{"sequence": 2, "kind": "step.started", "nodeId": "reserve", "payload": {"input": {"orderId": "A-200"}}, …}
{"sequence": 3, "kind": "step.retry-scheduled", "nodeId": "reserve", "payload": {"nodeId": "reserve", "attempt": 1, "nextDelayMs": 500, "previousError": "handler-error: Tool \"acme.reserve-stock\" handler threw: … Warehouse busy (503)"}, …}
{"sequence": 4, "kind": "step.retry-scheduled", "nodeId": "reserve", "payload": {"nodeId": "reserve", "attempt": 2, "nextDelayMs": 1000, "previousError": "handler-error: Tool \"acme.reserve-stock\" handler threw: … Warehouse busy (503)"}, …}
{"sequence": 5, "kind": "step.completed", "nodeId": "reserve", "payload": {"output": {"attempt": 3, "orderId": "A-200", "reserved": true}}, …}
```

## The policy

`policy.retry`:

- **`maxAttempts`:** attempts in all, the first one included, at most 10.
- **`delayMs`:** the wait before the first retry, 0 by default.
- **`backoff`:** how the wait grows.
  - `fixed`, the default: the same wait each time.
  - `linear`: `delayMs` × the retry's number.
  - `exponential`: doubling each time, 500, 1000, 2000 ms here. It needs
    **`maxDelayMs`**, the longest wait.

When the last attempt fails, the step fails and so does the run, with the last
error. A step [left for the run's next resume](#a-step-whose-read-failed)
uses one of its attempts too.

`policy.timeoutMs` limits each attempt. An attempt that takes longer is
stopped and counts as a failed attempt. Without retries, the step fails with
`reason: "timeout"`:

```json
{"sequence": 3, "kind": "step.failed", "nodeId": "reserve", "payload": {"reason": "timeout", "limitMs": 5, "message": "Handler for node \"reserve\" exceeded timeout of 5ms", "elapsedMs": 68}, …}
```

That entry came from `timeoutMs: 5`, set that low to show it.

:::caution
Retry only a step that is safe to run twice. A tool that failed may have done
part of its work: a payment that timed out may still have gone through. Make
the tool idempotent, such as by passing the order id to the API as its
idempotency key, or don't retry it.
:::

## A step whose read failed

An agent's step first reads what its turn needs from the runtime's database:
the agent's registration and live pin, the versions shipped into its
project, the gate policy, and its turn's snapshot and journal. When one of
those reads fails, such as when the database doesn't answer, the step
doesn't fail. It's left for the run's next resume:

```json
{"sequence": 3, "kind": "step.retry-scheduled", "nodeId": "draft", "payload": {"nodeId": "draft", "attempt": 1, "nextDelayMs": 0, "previousError": "run-version-unreadable: Could not read …", "left": true}, …}
```

- **Its `step.retry-scheduled` entry says `left: true`,** with `nextDelayMs`
  0 and the read's error in `previousError`.
- **The run stays `running`.** Steps running beside it finish first.
- **The run is resumed once its lease runs out,** 5 minutes by default
  ([If the runtime stops](../../../concepts/runs/#if-the-runtime-stops)),
  and the step runs again. A step in a loop, a fan-out or a subflow is left
  with the whole loop, fan-out or subflow step, and the resume replays from
  the journal what had finished.
- **The runtime logs it at `WARN`:**
  `flow run <run-id>'s step "<node-id>" was left for the run's next resume: the gate policy couldn't be read`,
  naming the read.

A leave uses one of the step's attempts under `retry.maxAttempts`, so a
retry after it has one attempt fewer. A step is left 3 times at most. Its
fourth failed read is a failed attempt like any other: it's retried if the
policy has attempts left, and otherwise the step fails with the read's
error, and so does the run.

A step isn't left when its read finds nothing, such as an agent that isn't
registered: that's a failed attempt. Nor is one whose read was cut short by
its `timeoutMs` or by the run's cancel.

A subflow's child run that's left with its parent's subflow step is held
for its parent. It stays `running`, and only the parent's resume resumes it:
a resume of the child itself is refused with `run-held-by-parent`. Once the
parent's subflow step has been left 3 times, the child's step fails with the
read's error, and the parent's subflow step fails with `child-failed`.

## Where a policy applies

A policy applies to the step its edge leads to, when that step has exactly one
incoming edge. A step that joins branches, with several incoming edges,
ignores the policies on them. The other policy fields, `concurrencyKey` and
`priority`, are in the [flow schema](../../../reference/schemas/flow/).
