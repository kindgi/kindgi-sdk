import { Tabs, TabItem } from '@astrojs/starlight/components';

This guide makes each turn of a long conversation wait for a reviewer, once
the conversation has run a number of turns.

Some conversations should get a person's attention once they run long: a
support chat that hasn't been resolved in a few turns, say. `hitl.afterTurns`
lets the first turns of a conversation run, then makes each turn after them
wait for a reviewer before it starts.

## Before you start

- **An agent,** in a pack on a runtime such as `kindgi dev`, with Kindgi
  0.2's CLI. This guide uses `acme-ops.echo-agent`, from a sample pack named
  `acme-ops` (`kindgi init acme-ops --template=sample`).
- **A reviewer's role.** Under `kindgi dev`, you're an `admin` reviewer.
  [Decide an approval](../decide-an-approval/) shows how to become one
  elsewhere.

## Set the limit

Give the agent's conversation policy a limit. Ask your coding agent: "Once a
conversation runs long, make my agent wait for a person before each turn."
For reference, it adds a limit like this:

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts excerpt
// in agents/echo-agent/index.ts
  conversationPolicy: { historyLimit: 10, hitl: { afterTurns: 2 } },
```

</TabItem>
<TabItem label="Python">

```python excerpt
# in agents/echo_agent.py
    conversation_policy={"historyLimit": 10, "hitl": {"afterTurns": 2}},
```

</TabItem>
<TabItem label="Java">

```java excerpt
// in src/main/java/acmeops/agents/EchoAgent.java
      .set("conversationPolicy", Map.of("historyLimit", 10, "hitl", Map.of("afterTurns", 2)))
```

</TabItem>
<TabItem label="Scala">

```scala excerpt
// in src/main/scala/acmeops/agents/EchoAgent.scala
    .set("conversationPolicy", Map("historyLimit" -> 10, "hitl" -> Map("afterTurns" -> 2)))
```

</TabItem>
</Tabs>

`afterTurns: 2` lets two turns run as usual. From the third on, each turn of
the same conversation waits for an approval before it runs.

## Try it

Start a conversation, then continue it twice. `--agent` is the agent, and
`--input` its input. `<conversation-id>` is the `conversationId` the first
turn returns, in its `output`:

<TabItem label="TypeScript">

pnpm exec kindgi runs start --agent=acme-ops.echo-agent --input='{"userMessage":"Can you refund it?","conversationId":"<conversation-id>"}'

## Approve or reject

Decide the approval to let the turn run or stop it. `<approval-id>` is the
approval's `id` from the list:

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```sh
pnpm exec kindgi approvals complete <approval-id> --decision=approve
```

</TabItem>
<TabItem label="Python">

```sh
uv run kindgi approvals complete <approval-id> --decision=approve
```

</TabItem>
<TabItem label="Java">

```sh
./kindgiw approvals complete <approval-id> --decision=approve
```

</TabItem>
<TabItem label="Scala">

```sh
./kindgiw approvals complete <approval-id> --decision=approve
```

</TabItem>
</Tabs>

It prints the recorded decision as JSON: the approval, the decision, and what
it did to the run. The turn runs, and it's the
conversation's third: the run's output has `"turnNumber": 3`. The next turn
asks again: every turn past the limit needs its own approval.

Reject, and the run fails without calling the model. `--rationale` is kept
with the decision. Then get the run by its id:

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```sh
pnpm exec kindgi approvals complete ff98fdd3-5d1d-4245-bdab-2ab9971f3962 --decision=reject --rationale="Hand this one to a person"
pnpm exec kindgi runs get 0c424165-fc78-4563-965f-5ca9ba0ec4a9
```

</TabItem>
<TabItem label="Python">

```sh
uv run kindgi approvals complete ff98fdd3-5d1d-4245-bdab-2ab9971f3962 --decision=reject --rationale="Hand this one to a person"
uv run kindgi runs get 0c424165-fc78-4563-965f-5ca9ba0ec4a9
```

</TabItem>
<TabItem label="Java">

```sh
./kindgiw approvals complete ff98fdd3-5d1d-4245-bdab-2ab9971f3962 --decision=reject --rationale="Hand this one to a person"
./kindgiw runs get 0c424165-fc78-4563-965f-5ca9ba0ec4a9
```

</TabItem>
<TabItem label="Scala">

```sh
./kindgiw approvals complete ff98fdd3-5d1d-4245-bdab-2ab9971f3962 --decision=reject --rationale="Hand this one to a person"
./kindgiw runs get 0c424165-fc78-4563-965f-5ca9ba0ec4a9
```

</TabItem>
</Tabs>

```json
{
  "id": "0c424165-fc78-4563-965f-5ca9ba0ec4a9",
  …
  "status": "failed",
  …
  "failureMessage": "{\"__agent_turn_failure__\":true,\"error\":{\"code\":\"hitl-rejected\",\"message\":\"Reviewer rejected the session-HITL gate: Hand this one to a person\",\"rationale\":\"Hand this one to a person\"}}"
}
```

A rejected turn doesn't count: the conversation still has two turns, and the
next message asks again.

You need to be a reviewer to see and decide these, as
[Decide an approval](../decide-an-approval/) shows.
