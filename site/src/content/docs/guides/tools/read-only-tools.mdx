This guide marks a tool that only reads, so dry runs run it, approval
gates let it through, and an agent can run its calls at the same time as
other read-only calls.

## Before you start

- **A tool,** in the quickstarts' pack, `my-pack`, with `kindgi dev` running
  and Kindgi 0.2's CLI.

## Mark it read-only

A tool declares whether it changes anything outside Kindgi. One that only
reads, such as a lookup, a search or a calculation, says so. Ask your coding
agent: "My order lookup tool only reads. Mark it read-only." Kindgi's skills
in your pack tell it how ([How it knows Kindgi](../../../start/coding-agents/)).
For reference, the tool's definition then looks like this:

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts excerpt
// in tools/lookup-order/index.ts
const defined = defineTool({
  id: 'my-pack.lookup-order' as ToolId,
  // …
  effects: [],
  mutating: false,
  // …
});
```

</TabItem>
<TabItem label="Python">

```python excerpt
# in tools/lookup_order.py
@tool(id="my-pack.lookup-order", mutating=False)
def lookup_order(ref: OrderRef, ctx: ToolContext) -> Order:
    ...
```

</TabItem>
<TabItem label="Java">

```java excerpt
// in src/main/java/mypack/tools/LookupOrder.java
  public static final Tool<Input, Output> TOOL = Tool.define("my-pack.lookup-order")
      // …
      .mutating(false)
      // …
```

</TabItem>
<TabItem label="Scala">

```scala excerpt
// in src/main/scala/mypack/tools/LookupOrder.scala
  val tool: Tool[Input, Output] = Tool[Input, Output]("my-pack.lookup-order")
    // …
    .readOnly
    // …
```

</TabItem>
</Tabs>

Leaving `mutating` out is the same as `mutating: true`. That's the safe
default: a tool counts as one that changes things until it says otherwise.
It decides three things: whether the tool runs in a dry run, whether an
approval gate asks before it, and whether an agent can run its calls at the
same time as others.

the tool is read-only. `--flow` is the flow, and `--input` its input:

## Effects

`effects` lists what a tool touches, for review and policy:
`{ kind: 'writes', resource: 'external:orders' }`. The kinds are `reads`,
`writes`, `deletes`, `network`, `spawns-run`, `emits-event`,
`external-side-effect` and `sensitive-data-egress`.

A tool with a `writes`, `deletes`, `spawns-run`, `emits-event` or
`external-side-effect` effect doesn't run in a dry run, and an agent runs
each call to it on its own, even when it says `mutating: false`. Keep the two consistent: a tool that only reads declares
`mutating: false` and, at most, `reads` effects.

## Approval gates

An agent can make a person approve tool calls, as
[Ask before a tool runs](../../approvals/ask-before-a-tool-runs/) shows. With
its gates on and no rule for a tool, a read-only tool runs without asking.
Any other tool waits for approval on its first use.

## Calls that run together

A model can ask for several tool calls in one step. An agent runs calls to
read-only tools that come one after another at the same time, up to 8 of them,
and a call to any other tool on its own, in the order the model asked (runtime
0.3.0 or later; earlier ones run every call on its own). A call to a read-only
tool that may wait, for [another system's answer](../wait-for-another-system/)
or for the person who started the run to [connect an app](../../connections/),
runs on its own too. Once a call needs an approval, the step's calls that
haven't started run one at a time. Either way, the results reach the
conversation and the model in the order the model asked for them, and each
call's events carry its own duration.

To run every call on its own, set `parallelToolCalls: false` on the agent
(`parallel_tool_calls=False` in Python, `set("parallelToolCalls", false)` in
Java and Scala). Do that when its read-only tools mustn't overlap, such as two
lookups against an API that allows one request at a time. An earlier runtime
accepts the setting and runs every call on its own anyway.

## Getting it right

- Declare `mutating: false` on every tool that only reads. Otherwise a dry
  run stops at it, an approval gate asks before it, and an agent runs each
  call to it on its own.
- Never declare it on a tool that writes, sends or deletes. A dry run would
  then run it for real, and an agent could run it at the same time as other
  calls.
- A tool from an [MCP server](../mcp-servers/) always counts as one that
  changes things: it doesn't run in a dry run.
