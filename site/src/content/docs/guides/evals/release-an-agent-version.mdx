A run that names no version gets the agent's latest version. Once a new
version has done better on your test set (see
[Compare a version on a test set](../compare-an-agent-version/)), you can make
it **live** where you choose: the whole tenant, an org, a project, or a
segment of a project's runs, such as one company's. Runs there use it from the
next run, nothing changes anywhere else, and you can roll back at once.

## Make a version live

`acme.order-desk` has versions 1.0.0, 1.1.0 and 1.2.0. Make 1.0.0 live for the
whole tenant:

```sh
kindgi agents promote acme.order-desk 1.0.0 --tenant --reason="1.0.0 is the version we checked"
```

```json
{
  "id": "ea4e7c15-7990-41b6-b153-0847a83f2e9d",
  "agentId": "acme.order-desk",
  "scope": { "kind": "tenant" },
  "action": "promote",
  "fromVersion": null,
  "toVersion": "1.0.0",
  "requestedBy": { "kind": "user", "id": "5c0a7e11-0000-4000-8000-0000000000aa" },
  "reason": "1.0.0 is the version we checked",
  "createdAt": "2026-10-06T18:46:15.125Z"
}
```

From the next run, a run that names no version gets 1.0.0, and says why:

```sh
kindgi runs start --agent=acme.order-desk --input='{"userMessage":"Where is order A-1002?"}'
```

```json
  "agent": {
    "id": "acme.order-desk",
    "version": "1.0.0",
    "conversationId": "4af092ea-5e8e-42f1-832e-b7ba1ed6e3d8",
    "via": "live",
    "liveScope": { "kind": "tenant" }
  },
```

`via` says how the run got its version:

| `via` | The version is |
| --- | --- |
| `live` | the live version of the scope in `liveScope` |
| `latest` | the latest, because nothing is live for this run |
| `explicit` | the one the run named (`--agent-version`, `agentVersion`) |
| `conversation` | the one its conversation started with (see below) |

A version only goes live this way: publishing a newer version doesn't change
what a scope with a live version runs.

## Make it live for some runs only

The most specific live version wins, in this order: a **segment** path in a
project, the **project**, the project's **org**, the **tenant**, and then the
latest version. A segment path is one or more `key:value` steps, coarse to
fine, that a run is started with: `company:acme`, or `company:acme` then
`role:counsel`.

Try 1.1.0 with acme's runs only:

```sh
kindgi agents promote acme.order-desk 1.1.0 --project=<project-id> --segment=company:acme --reason="Trying 1.1.0 with acme first"
```

A run started with that segment gets 1.1.0:

```sh
kindgi runs start --agent=acme.order-desk --project=<project-id> --segment=company:acme --input='{"userMessage":"Where is order A-1002?"}'
```

```json
  "agent": {
    "id": "acme.order-desk",
    "version": "1.1.0",
    "conversationId": "d35be284-99c0-4437-9186-b951386db8b3",
    "via": "live",
    "liveScope": {
      "kind": "segment",
      "projectId": "367e1657-8067-4a1d-8ec4-bfa3c5fc5865",
      "path": [{ "key": "company", "value": "acme" }]
    }
  },
```

A run with `--segment=company:globex` has no live version of its own, so it
gets the tenant's, 1.0.0. `--tenant`, `--org=<org-id>` and
`--project=<project-id>` name the other scopes; without `--project`, a run is
in the Default project (`kindgi projects list` lists the ids).

## See which version a run would get

`kindgi agents live` answers without starting a run:

```sh
kindgi agents live acme.order-desk --project=<project-id> --segment=company:acme
```

```json
{
  "agentId": "acme.order-desk",
  "version": "1.1.0",
  "via": "live",
  "liveScope": {
    "kind": "segment",
    "projectId": "367e1657-8067-4a1d-8ec4-bfa3c5fc5865",
    "path": [{ "key": "company", "value": "acme" }]
  }
}
```

`kindgi agents live-versions acme.order-desk` lists every scope with a live
version, and since when.

## From your app

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts
// release.ts
import { createClient } from '@kindgi/sdk/client';

const kindgi = createClient(); // KINDGI_API_URL, KINDGI_API_TOKEN, or the running kindgi dev
const projectId = process.argv[2];
const acme = [{ key: 'company', value: 'acme' }];

// Make 1.1.0 live for acme's runs in this project.
await kindgi.agents.promotions.create('acme.order-desk', {
  version: '1.1.0',
  scope: { kind: 'segment', projectId, path: acme },
  reason: 'Trying 1.1.0 with acme first',
});

// Which version would a run there use, and why?
const live = await kindgi.agents.live.resolve('acme.order-desk', { projectId, segments: acme });
console.log(live.version, live.via, live.liveScope?.kind);

// A run that names no version gets it.
const run = await kindgi.runs.start({
  agent: 'acme.order-desk',
  projectId,
  segments: acme,
  input: { userMessage: 'Where is order A-1002?' },
});
console.log(run.agent?.version, run.agent?.via);
```

## Conversations keep their version

A follow-up turn in a conversation keeps the version the conversation started
with, even after a promotion: the conversation stays consistent. Here a
conversation started on 1.2.0, before 1.0.0 went live for the tenant, and its
next turn still ran 1.2.0:

```json
  "agent": {
    "id": "acme.order-desk",
    "version": "1.2.0",
    "conversationId": "9fce3360-5426-4578-b387-361afa9f2156",
    "via": "conversation"
  },
```

A new conversation gets the live version.

## Roll back, or unpin

`kindgi agents rollback` puts a scope back on the version that was live there
before (or on `--to=<version>`), at once:

```sh
kindgi agents rollback acme.order-desk --tenant --reason="1.2.0 answers worse"
```

```json
{
  "id": "7da674c5-c835-42c0-8cde-59571afd0915",
  "agentId": "acme.order-desk",
  "scope": { "kind": "tenant" },
  "action": "rollback",
  "fromVersion": "1.2.0",
  "toVersion": "1.0.0",
  …
}
```

`kindgi agents unpin` removes a scope's own live version: its runs then use
the scope above, or the latest version when nothing above is live.

```sh
kindgi agents unpin acme.order-desk --tenant --reason="Back to the latest"
```

What each refuses:

- a version that isn't registered:
  `Version 9.9.9 is not registered (or was unregistered)`;
- a rollback where nothing was live before:
  `The scope had no live version before this one: unpin it to fall back to the scope above`;
- an unpin where the scope has no live version of its own:
  `The scope has no live version of its own`.

## In the console

- An agent's page says which version a run in this project gets, such as
  "Runs here use 1.0.0", and why: "It's live for every project (the
  tenant-wide default)." It links to its **Live versions** page.
- **Live versions** has the same headline, **Check a segment path** (a key
  and a value) to see what a run on a path would get, every pin that reaches
  this project with its part ("Runs here take it", or "Runs on this path take
  it" for a segment), each with **Roll back** and **Unpin**, and the history
  with who and why.
- **Promote a version** picks the version and the scope: this project, every
  project in its org (when it's in one), every project, or a segment path in
  this project. It says what will happen before you promote, such as "Runs in
  this project (Support) will use 1.3.0."
- A run's page says why it ran its version, such as "Live for company = acme
  in this project (Default)".
