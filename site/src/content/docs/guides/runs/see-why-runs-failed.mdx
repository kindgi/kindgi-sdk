This guide finds why one run failed, and counts a project's failed runs by
cause and by version, so a version that fails in a new way stands out.

## Before you start

- **Failed runs,** on a runtime such as `kindgi dev`, with Kindgi 0.2's CLI.
- **For the app's half:** Node 22.12 or later, Python 3.11 or later, or
  Java 17 or later, with Kindgi 0.2's client, `KINDGI_API_URL` and
  `KINDGI_API_TOKEN` set, and `read` on the project.

## Why one run failed

A failed run says why in its `failure`. Read the run:

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```sh
pnpm exec kindgi runs get <run-id>
```

</TabItem>
<TabItem label="Python">

```sh
uv run kindgi runs get <run-id>
```

</TabItem>
<TabItem label="Java">

```sh
./kindgiw runs get <run-id>
```

</TabItem>
<TabItem label="Scala">

```sh
./kindgiw runs get <run-id>
```

</TabItem>
</Tabs>

`<run-id>` is the failed run's id. In the clients, it's `runs.get`, and over
HTTP `GET /v1/runs/{runId}`. Here a guardrail halted an agent's turn:

```json
{
  "id": "143475bd-9e28-49cf-9f68-d03d081317ef",
  …
  "flowId": "agent.turn",
  "flowVersion": "1.1.0",
  "status": "failed",
  …
  "completedAt": "2026-10-11T07:27:40.781Z",
  …
  "failure": {
    "code": "guardrail-violation",
    "message": "Turn blocked by guardrail 'acme.no-secret': output contains forbidden pattern(s): SECRET"
  },
  "agent": {
    "id": "acme.refunds",
    "version": "1.1.0",
    …
  },
  …
}
```

- **`code`:** the error's own code, such as `guardrail-violation`,
  `capability-routing-failed` or `budget-exceeded`. It's `run-failed` when
  the error has none.
- **`message`:** what happened.
- **`reason`:** the error's own reason, when it gives one. A turn whose
  approval was cancelled, `hitl-cancelled`, has `timeout` when nobody decided
  in time.
- **`cause`:** what the error came from, when it says. A turn that no model
  could serve, because the agent needs a feature no registered model has:

  ```json excerpt
  "failure": {
    "code": "capability-routing-failed",
    "message": "No registered provider satisfies the capability declaration",
    "cause": {
      "code": "capability-unsatisfiable",
      "message": "No registered provider satisfies the capability declaration",
      "reasons": []
    }
  }
  ```

Read `failure`, not `failureMessage`. `failureMessage` is the failure as the
runtime recorded it, in its own format: for an agent's turn, that's JSON
meant for the runtime.

## A project's failed runs, by cause and version

Counting a window's failed runs by cause and version shows a version that
fails in a new way as a line of its own. Ask your coding agent: "I want my
app to count a project's failed runs from the last week, by cause and
version." For reference, this function prints a project's failed runs of the
last week:

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts
// app/failures.ts
import { createClient } from '@kindgi/sdk/client';

const kindgi = createClient(); // KINDGI_API_URL, KINDGI_API_TOKEN

/** Prints a project's failed runs of the last week, by cause and version. */
export async function printFailures(projectId: string) {
  const to = new Date();
  const from = new Date(to.getTime() - 7 * 24 * 60 * 60 * 1000); // the last week
  const failures = await kindgi.runs.failures({ projectId, from, to });
  for (const g of failures.groups) console.log(g.code, g.subject.id, g.version, g.count);
  for (const g of failures.outcomes) console.log(g.code, g.subject.id, g.version, g.count);
  for (const g of failures.unrecorded) console.log('unrecorded', g.subject.id, g.version, g.count);
}
```

```text
guardrail-violation acme.refunds 1.1.0 3
capability-routing-failed acme.vision 1.0.0 1
hitl-rejected acme.desk 1.0.0 1
unrecorded acme.refunds 1.0.0 2
```

</TabItem>
<TabItem label="Python">

```python
# app/failures.py
from datetime import datetime, timedelta, timezone

from kindgi.client import Kindgi

kindgi = Kindgi()  # KINDGI_API_URL, KINDGI_API_TOKEN


def print_failures(project_id: str) -> None:
    """Prints a project's failed runs of the last week, by cause and version."""
    to = datetime.now(timezone.utc)
    failures = kindgi.runs.failures(
        project_id=project_id, from_=(to - timedelta(days=7)).isoformat(), to=to.isoformat()
    )
    for g in failures.groups:
        print(g.code, g.subject.id, g.version, g.count)
    for g in failures.outcomes:
        print(g.code, g.subject.id, g.version, g.count)
    for g in failures.unrecorded:
        print("unrecorded", g.subject.id, g.version, g.count)
```

capability-routing-failed acme.vision 1.0.0 1
hitl-rejected acme.desk 1.0.0 1

<TabItem label="Java">

```java
// src/main/java/com/acme/app/Failures.java
package com.acme.app;

import com.kindgi.client.Kindgi;
import com.kindgi.client.models.FailureGroup;
import com.kindgi.client.models.RunFailureGroups;
import com.kindgi.client.resources.RunsFailuresParams;
import java.time.OffsetDateTime;
import java.time.ZoneOffset;

public final class Failures {
  private static final Kindgi kindgi = Kindgi.create(); // KINDGI_API_URL, KINDGI_API_TOKEN

  /** Prints a project's failed runs of the last week, by cause and version. */
  public static void printFailures(String projectId) {
    OffsetDateTime to = OffsetDateTime.now(ZoneOffset.UTC);
    OffsetDateTime from = to.minusDays(7); // the last week
    RunFailureGroups failures = kindgi.runs().failures(
        RunsFailuresParams.builder().projectId(projectId).from(from).to(to).build());
    for (FailureGroup g : failures.groups()) {
      System.out.println(g.code() + " " + g.subject().id() + " " + g.version() + " " + g.count());
    }
    for (FailureGroup g : failures.outcomes()) {
      System.out.println(g.code() + " " + g.subject().id() + " " + g.version() + " " + g.count());
    }
    for (FailureGroup g : failures.unrecorded()) {
      System.out.println("unrecorded " + g.subject().id() + " " + g.version() + " " + g.count());
    }
  }

  private Failures() {}
}
```

On a project where two turns of `acme.echo-agent` failed because their
conversation was closed, and two runs of `acme.review-order` failed, it
prints:

```text
conversation-closed acme.echo-agent 0.1.0 2
run-failed acme.review-order 0.1.0 2
```

In this project, version 1.1.0 of `acme.refunds` had three turns halted by a
guardrail, and `acme.vision` one turn no model could serve. A reviewer
rejected a turn of `acme.desk`. Two turns of `acme.refunds` 1.0.0 failed with
no cause recorded.

The answer in full, as `GET /v1/runs/failures?projectId=…&from=…&to=…`
gives it:

```json
{
  "from": "2026-10-11T07:26:28.000Z",
  "to": "2026-10-11T07:28:44.000Z",
  "groups": [
    {
      "code": "guardrail-violation",
      "subject": { "kind": "agent", "id": "acme.refunds" },
      "version": "1.1.0",
      "count": 3,
      "firstSeen": "2026-10-11T07:27:39.298Z",
      "lastSeen": "2026-10-11T07:27:40.781Z",
      "exampleRunId": "143475bd-9e28-49cf-9f68-d03d081317ef"
    },
    {
      "code": "capability-routing-failed",
      "subject": { "kind": "agent", "id": "acme.vision" },

      "subject": { "kind": "agent", "id": "acme.desk" },
      "version": "1.0.0",
      "count": 1,

      "lastSeen": "2026-10-11T07:27:44.263Z",

    {
      "subject": { "kind": "agent", "id": "acme.refunds" },
      "version": "1.0.0",
      "count": 2,
      "firstSeen": "2026-10-11T07:27:33.045Z",
      "lastSeen": "2026-10-11T07:27:33.712Z",
      "exampleRunId": "23f69746-a744-40a6-94c3-89b45d772f91"
    }
  ],
  "total": 7
}
```

- **`groups`:** failed runs with the same cause (`code`), subject and version,
  the most first. The subject is an agent, for its turns, or a flow, for its
  runs. The version is the agent's or the flow's. `count` is how many failed
  in the window. `firstSeen` and `lastSeen` are when the first and the latest
  did, and `exampleRunId` is the latest, to open.
- **`outcomes`:** people's decisions, which aren't errors. A turn a reviewer
  rejected is `hitl-rejected`. A turn whose approval was cancelled is
  `hitl-cancelled`, with `reason: "timeout"` when nobody decided in time.
- **`unrecorded`:** failed runs with no cause recorded, such as runs an
  older runtime ran. They're counted by subject and version only.
- **`total`:** every failed run in the three lists.

What's counted:

- **`from` and `to`** are when the runs failed, at most 90 days apart.
- **Replays, the runs an eval run makes, and dry runs** aren't counted. A turn
  inside a flow counts under its agent, and the flow's run under the flow.
- **Failed runs go with their retention,** so a window can hold fewer than
  failed then.
- **Each list** holds 50 groups at most. `limit` raises it, up to 200.

It needs `read` on the project.

### One agent, by version

`agentId` (or `flowId`) counts one subject's runs. `groupBy: ['version']`
(`group_by="version"`) groups them by version alone, without the cause:

```json
{
  "from": "2026-10-11T07:26:28.000Z",
  "to": "2026-10-11T07:28:44.000Z",
  "groups": [
    {
      "subject": { "kind": "agent", "id": "acme.refunds" },
      "version": "1.1.0",
      "count": 3,
      "firstSeen": "2026-10-11T07:27:39.298Z",
      "lastSeen": "2026-10-11T07:27:40.781Z",
      "exampleRunId": "143475bd-9e28-49cf-9f68-d03d081317ef"
    }
  ],
  "outcomes": [],
  "unrecorded": [
    {
      "subject": { "kind": "agent", "id": "acme.refunds" },
      "version": "1.0.0",
      "count": 2,
      "firstSeen": "2026-10-11T07:27:33.045Z",
      "lastSeen": "2026-10-11T07:27:33.712Z",
      "exampleRunId": "23f69746-a744-40a6-94c3-89b45d772f91"
    }
  ],
  "total": 5
}
```

`groupBy: ['code']` groups by cause alone, across versions. The default is
both.

## In the console

A project's **What failed** page, under **Runs**, shows the same count for
24 hours, or 7, 30 or 90 days. For a project with seven failed runs in the
last week, it says "In the last 7 days, 7 runs failed: 4 errors (in 2
groups), 1 people's decision on approvals, 2 from before causes were
recorded.", then a table for each kind:
- **Errors,** by cause and version: "A guardrail blocked the answer." for
  acme.refunds 1.1.0, 3 runs; "No model provider could take the call." for
  acme.vision 1.0.0, 1 run.
- **People's decisions on approvals:** "A reviewer rejected it, it was
  withdrawn, or no one decided in time: an outcome, not an error."
- **From before causes were recorded:** "These failed on a runtime that didn't
  record why; each run's page shows its message."

Each row opens its latest run and its failed runs.
[What failed](../list-runs/#what-failed) has the rest of the page.

A failed run's page names its cause in the same words, then the runtime's
own and the code. A turn a guardrail halted keeps the answer back: "Blocked
by a guardrail, not sent: the answer the model wrote", with **Show what was
blocked**. It names the guardrail, and folds the guardrail's reason, since a
reason can quote what the guardrail blocked, such as a card number:

```text
A guardrail blocked the answer.
Show why it was blocked
Guardrail: acme.no-secret
Code guardrail-violation
```

**Show why it was blocked** opens it: "Turn blocked by guardrail
'acme.no-secret': output contains forbidden pattern(s): SECRET". A flow
step's error folds it the same way.
