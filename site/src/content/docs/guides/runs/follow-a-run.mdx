A run's events are its journal as it's written: the run starting, each step
starting and ending, waits, and the run's end. Follow them to show progress,
or to react when the run ends without polling.

Ask your coding agent: "I want my app to show a run's progress as it
happens." For reference, the code looks like this. It starts a run in the
background, then prints each event until the run ends:

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts
// scripts/follow-a-run.ts
import { createClient } from '@kindgi/sdk/client';

const kindgi = createClient();

const run = await kindgi.runs.start({
  flow: 'acme.reserve-order',
  input: { orderId: 'A-400' },
  options: { wait: false },
});

for await (const event of kindgi.runs.follow(run.id)) {
  console.log(event.sequence, event.kind, event.nodeId ?? '');
}
// The loop ends after run.completed, run.failed or run.cancelled.
```

```text
2 run.step-started reserve
3 run.step-retry-scheduled reserve
4 run.step-retry-scheduled reserve

```

```java
// src/main/java/com/acme/app/FollowRun.java
package com.acme.app;

import com.kindgi.client.EventStream;
import com.kindgi.client.Kindgi;
import com.kindgi.client.models.Run;
import com.kindgi.client.models.RunEvent;
import com.kindgi.client.models.StartRunBody;
import java.util.Map;
import java.util.Objects;

public final class FollowRun {
  public static void main(String[] args) {
    Kindgi kindgi = Kindgi.create();

    Run run = kindgi.runs().start(StartRunBody.WithFlow.builder()
        .flow("acme.reserve-order")
        .input(Map.of("orderId", "A-400"))
        .options(StartRunBody.WithFlow.Options.builder().wait_(false).build())
        .build());

    try (EventStream<RunEvent> events = kindgi.runs().follow(run.id())) {
      for (RunEvent event : events) {
        System.out.println(event.sequence() + " " + event.kind() + " " + Objects.toString(event.nodeId(), ""));
      }
    }
    // The loop ends after run.completed, run.failed or run.cancelled.
  }
}
```

```scala
// src/main/scala/acme/app/FollowRun.scala
package acme.app

import com.kindgi.client.Kindgi
import com.kindgi.client.models.StartRunBody
import scala.jdk.CollectionConverters._
import scala.util.Using

object FollowRun {
  def main(args: Array[String]): Unit = {
    val kindgi = Kindgi.create()

    val run = kindgi.runs().start(StartRunBody.WithFlow.builder()
      .flow("acme.reserve-order")
      .input(Map("orderId" -> "A-400").asJava)
      .options(StartRunBody.WithFlow.Options.builder().wait_(false).build())
      .build())

    Using.resource(kindgi.runs().follow(run.id)) { events =>
      events.forEachRemaining { event =>
        println(s"${event.sequence} ${event.kind} ${Option(event.nodeId).getOrElse("")}")
      }
    }
    // The loop ends after run.completed, run.failed or run.cancelled.
  }
}
```

The stream starts from the run's first event, whenever you open it, so you
don't miss what happened before. It ends after `run.completed`, `run.failed` or
`run.cancelled`; the last event's `payload.output` is the run's output. A
step [left for the run's next resume](../../flows/retry-a-step/#a-step-whose-read-failed)
doesn't end it: the run is still running.

## The events

Each event has the run's id, a `kind`, a `sequence` (its place in the
journal), a `timestamp`, the step's `nodeId` for step events, and a `payload`:

| `kind` | When | `payload` |
| --- | --- | --- |
| `run.started` | The run started. | `input` |
| `run.step-started` | A step started. | `input` |
| `run.step-completed` | A step ended. | `output` |
| `run.step-failed` | A step failed. | `message` |
| `run.step-retry-scheduled` | A step failed and will be [retried](../../flows/retry-a-step/), or, with `left: true`, was [left for the run's next resume](../../flows/retry-a-step/#a-step-whose-read-failed). | `attempt`, `nextDelayMs`, `previousError`, `left`, `childRunId` |
| `run.iteration-started`, `run.iteration-completed` | A pass of a [loop](../../flows/loop/). | `iteration`, … |
| `run.wait-suspended`, `run.wait-resumed` | The run stopped to wait, and went on ([approvals](../../flows/wait-for-an-approval/)). | |
| `run.completed` | The run completed. | `output` |
| `run.failed` | The run failed. | `message` |
| `run.cancelled` | The run was cancelled. | |

Edge decisions are in the [journal](../read-the-journal/), not in the stream.

## Reconnecting

The server ends a stream after 5 minutes; a run that waits longer needs a new
one. Each event's id is `<run id>:<sequence>`, and a new stream opened with
the last id you saw (the `Last-Event-Id` header) starts after it.

`runs.follow` does this for you, in TypeScript, Python, Java and Scala (the
Java client's `runs().follow`): it reconnects after a dropped connection or
the server's limit, and ends only with the run. `runs.followProgress`
(Python: `runs.follow_progress`; Java: `runs().followProgress`) follows the
[progress stream](../follow-from-the-browser/) (no payloads) the same way.

- In Python, `runs.stream` is the plain call: it ends when the server closes
  the stream, and `last_event_id=f"{run.id}:{event.sequence}"` opens it again
  after that event.
- In Java and Scala, `runs().stream(runId)` is the plain call too, and
  `RunsStreamParams.builder().lastEventId(…)` opens it again after an event.
- In TypeScript, `runs.stream` still follows the run to its end, as `follow`
  does, but it's deprecated: in a later release, announced in advance, it
  becomes the plain call, as in Python.

It prints one event per line, as JSON:

```text

{"eventId":"28795fe7-a357-4d67-8740-1bda88f3b85c:2",…,"kind":"run.step-started","sequence":2,"nodeId":"reserve","payload":{"input":{"orderId":"A-300"}}}
…
{"eventId":"28795fe7-a357-4d67-8740-1bda88f3b85c:7",…,"kind":"run.completed","sequence":7,"payload":{"output":{"attempt":3,"orderId":"A-300","reserved":true}}}
```

:::note
In this release, `kindgi runs stream` prints the events when the run ends,
all at once. To watch them arrive, use the client.
:::
