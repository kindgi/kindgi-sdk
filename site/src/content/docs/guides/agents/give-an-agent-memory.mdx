This guide keeps facts an agent reads before each turn, lets it remember what
it's told, and has it recall earlier conversations.

An agent's **memory** is facts the runtime keeps: a customer's preference,
a team's policy, what a person said last week. Before each turn, the agent
**retrieves** the facts its declaration asks for, and they reach the model as
data. An agent can also **remember** facts itself, under rules you set, and
**recall** its earlier conversations. [Memory reference](../memory-reference/)
has what a fact holds, how memory reaches the model, search by meaning, who
sees what, and the errors.

## Before you start

- **An agent,** in a pack on a runtime such as `kindgi dev`, with Kindgi
  0.1's CLI. This guide uses `acme.order-desk` and `acme.desk`.
- **A model with reliable tool calling,** for an agent that remembers.
- **An embeddings endpoint on the runtime,** for search by meaning, as
  [Search by meaning](../memory-reference/#search-by-meaning) shows. Without
  one, keyword search works.
- **Your app's id for each end user,** passed as `participantId` on their
  runs, for memory kept per end user.

## Write and read facts

A fact you write is one the agent can read before a turn. Ask your coding
agent to write the fact:

```text
I want my agents to know that a customer of mine orders spare parts for a washing machine.
```

For reference, the fact it writes looks like this. This guide writes it for
the customer `end-7`, gives it the type `acme.note`, and saves it as
`fact.json`, where `<project-id>` is your project's id:

```json
{"type":"acme.note","content":{"text":"end-7 orders spare parts for a washing machine."},"scope":{"projectId":"<project-id>","participantId":"end-7"}}
```

Write it:

## Retrieve facts before each turn

An agent's `retrieval` lists what it reads before each turn, so the model
sees the facts it needs. Each entry is a **retrieval intent**. Ask your
coding agent: "Before each turn, have my agent read the customer's
preferences." Kindgi's skills in your pack tell it how
([How it knows Kindgi](../../../start/coding-agents/)). For reference, it
adds one to the agent's definition:

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts excerpt
// in agents/order-desk/index.ts
  retrieval: [{ types: ['acme.preference'], scope: 'same-user', mode: 'both', limit: 5 }],
```

</TabItem>
<TabItem label="Python">

```python excerpt
# in agents/order_desk.py
    retrieval=[{"types": ["acme.preference"], "scope": "same-user", "mode": "both", "limit": 5}],
```

</TabItem>
<TabItem label="Java">

```java excerpt
// in src/main/java/acme/agents/OrderDesk.java
      .set("retrieval", List.of(
          Map.of("types", List.of("acme.preference"), "scope", "same-user", "mode", "both", "limit", 5)))
```

</TabItem>
<TabItem label="Scala">

```scala excerpt
// in src/main/scala/acme/agents/OrderDesk.scala
    .set("retrieval", Seq(
      Map("types" -> Seq("acme.preference"), "scope" -> "same-user", "mode" -> "both", "limit" -> 5)))
```

</TabItem>
</Tabs>

- **`types`:** the fact types it reads, at least one.
- **`scope`**, always within what the run may see:
  - `same-conversation`: this conversation's facts;
  - `same-user`: the facts of the conversation's end user only. A run that
    names no end user (`participantId`) reads none, and facts kept for the
    user a key acts for are never read as anyone's: a key may serve many
    people. The run's result carries a `memory-needs-participant` warning.
    Naming an end user (`participantId`) takes being that person, or `write`
    on the project, as reading their facts does: otherwise
    `403 participant-not-allowed`;
  - `same-project`: the run's project's facts (none in a run without one);
  - `tenant`: any fact of those types the run may see.
- **`mode`**, with the user's message as the query: none (the newest facts
  first), `keyword`, `semantic` (search by meaning), or `both` (the two,
  fused by rank).
- **`limit`:** at most this many facts per turn, 10 by default.

A turn never reads another conversation's or another end user's facts.

The agent's turns now read those facts first. They reach the model as data,
as [How memory reaches the model](../memory-reference/#how-memory-reaches-the-model)
describes. A run of a `same-user` agent that names no end user has this among
its result's `warnings`:

```json
{
  "code": "memory-needs-participant",
  "message": "Agent \"acme.desk\" keeps memory per end user, but this run names none (`participantId`), so it read and kept none. Pass the person's `participantId` on each run: the user a credential acts for may serve many people."
}
```

## Let an agent remember

An agent that remembers keeps what it's told for later turns. Ask your coding
agent: "Let my agent remember a customer's preferences." For reference,
it adds `remember` to the agent's `memory`:

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts excerpt
// in agents/order-desk/index.ts
  memory: { remember: { types: ['acme.preference'], scope: 'same-user', keepDays: 30 } },
```

</TabItem>
<TabItem label="Python">

```python excerpt
# in agents/order_desk.py
    memory={"remember": {"types": ["acme.preference"], "scope": "same-user", "keepDays": 30}},
```

</TabItem>
<TabItem label="Java">

```java excerpt
// in src/main/java/acme/agents/OrderDesk.java
      .set("memory", Map.of("remember", Map.of(
          "types", List.of("acme.preference"), "scope", "same-user", "keepDays", 30)))
```

</TabItem>
<TabItem label="Scala">

```scala excerpt
// in src/main/scala/acme/agents/OrderDesk.scala
    .set("memory", Map("remember" -> Map(
      "types" -> Seq("acme.preference"), "scope" -> "same-user", "keepDays" -> 30)))
```

</TabItem>
</Tabs>

The agent's turns then offer the built-in tool `kindgi_remember`. Name it in
the instructions as it is ("call kindgi_remember when the customer states a
preference"): built-in tools have no dots, so the model sees exactly that
name.

- **The model picks** the type (one of `types`), the text (up to 2,000
  characters), an optional `key` (a slot: the same key replaces the agent's
  earlier value) and when it stops being true.
- **It never picks the scope.** `same-user` is the conversation's end user:
  a run that names none (`participantId`) isn't offered the tool, and its
  result carries a `memory-needs-participant` warning. `same-conversation`,
  `same-project` and `tenant` are what they say.
- **`tenant` takes a tenant admin**
  [with authorization on](../../../deploy/authorization/): facts every
  project reads are a tenant-level decision. In a turn that a person or a
  key runs, the agent proposes one only when that caller is a tenant admin.
  With anyone else, the call doesn't run, and the model is told:

  ```text
  You don't have permission to remember facts for everyone in the organization: that needs a tenant admin.
  ```
- **Every remembered fact** is `unverified`, attributed to the agent version
  and the tool call that wrote it, and kept `keepDays` (30 by default) unless
  a person verifies it.
- **A person approves first** when the scope is wider than one person
  (`same-project`, `tenant`), or the text reads like an instruction ("always
  …", "ignore …", a link, a tool name). The approval is a `memory-fact`
  approval in the reviewers' list; until it's approved, no read sees the
  fact.

The agent remembers through a tool call, so it needs a model with reliable
tool calling. Some small local models write the call as text instead, and
nothing is remembered. [Models](../../models/) lists what each model
supports.

An agent with tool approval gates, `conversationPolicy.hitl.tools`, should
set `kindgi_remember` to `never_ask` in its `overrides`. Remembering changes
something, so otherwise every remember waits for a person. The rule about a
person approving first already decides which facts need one. See
[Ask before a tool runs](../../approvals/ask-before-a-tool-runs/).

Here `acme.desk`, whose instructions say to "call kindgi_remember to store it
before you answer", took a turn on a small local model. A real model's
wording differs. Its first call left out `type`. The tool's validation said
so, and it called again:

## Recall earlier conversations

Recall lets a turn see what the person said in earlier conversations. A
retrieval intent with `source: 'conversations'` recalls messages of this
agent's earlier conversations. It takes no `types`. Ask your coding agent:
"Let my agent see what a customer said in their earlier conversations."
For reference, the retrieval intent it writes looks like this:

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts excerpt
// in agents/order-desk/index.ts
  retrieval: [{ source: 'conversations', scope: 'same-user', mode: 'both', limit: 3 }],
```

</TabItem>
<TabItem label="Python">

```python excerpt
# in agents/order_desk.py
    retrieval=[{"source": "conversations", "scope": "same-user", "mode": "both", "limit": 3}],
```

</TabItem>
<TabItem label="Java">

```java excerpt
// in src/main/java/acme/agents/OrderDesk.java
      .set("retrieval", List.of(
          Map.of("source", "conversations", "scope", "same-user", "mode", "both", "limit", 3)))
```

</TabItem>
<TabItem label="Scala">

```scala excerpt
// in src/main/scala/acme/agents/OrderDesk.scala
    .set("retrieval", Seq(
      Map("source" -> "conversations", "scope" -> "same-user", "mode" -> "both", "limit" -> 3)))
```

</TabItem>
</Tabs>

- **`same-user`** (the usual choice): this end user's other conversations.
  A run that names no end user (`participantId`) recalls none, never the
  conversations of the user its key acts for, which may serve many people.
- **`same-conversation`:** this conversation's messages older than the
  history window.
- **`same-segment`:** conversations in the run's segment path (the same
  customer), whoever had them.
- **`same-project`:** the project's conversations, whoever had them.

A comparison's replays are never recalled, in any scope: a replay re-runs a
past turn on another version, and its answers are no one's.

**The people's own words, by default.** Recall returns users' messages only,
and the messages either side of a hit follow the same rule. `roles: ['user',
'agent']` adds the agent's earlier answers too. Those can carry its earlier
mistakes, so each one is quoted with `note: "earlier answer by the agent, not
verified"`, and publishing warns `recall-agent-answers`.

**Other people's conversations.** `same-segment` and `same-project` quote
them, in the run's own project only. Publishing warns `recall-other-people`,
and each of their messages is marked `anotherPerson`, without saying whose.

Recalled messages go in the `<memory>` block after the facts, as quotes from
an earlier conversation, never as turns of this one. A quote has the
conversation's date, the message and the ones either side. Here end user
`end-9` writes again about the same washing machine, and the turn recalls
what they said in an earlier conversation:

## Change, verify, delete

A fact changes by revision, so its history stays readable:

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```sh
pnpm exec kindgi memory facts supersede <fact-id> --input='{"content":"Prefers phone"}' --expect-version=1
pnpm exec kindgi memory facts verify <fact-id>
pnpm exec kindgi memory facts delete <fact-id>
pnpm exec kindgi memory facts revisions <fact-id>
pnpm exec kindgi memory facts get <fact-id> --as-of=2026-10-01T00:00:00Z
```

</TabItem>
<TabItem label="Python">

```sh
uv run kindgi memory facts supersede <fact-id> --input='{"content":"Prefers phone"}' --expect-version=1
uv run kindgi memory facts verify <fact-id>
uv run kindgi memory facts delete <fact-id>
uv run kindgi memory facts revisions <fact-id>
uv run kindgi memory facts get <fact-id> --as-of=2026-10-01T00:00:00Z
```

</TabItem>
<TabItem label="Java">

```sh
./kindgiw memory facts supersede <fact-id> --input='{"content":"Prefers phone"}' --expect-version=1
./kindgiw memory facts verify <fact-id>
./kindgiw memory facts delete <fact-id>
./kindgiw memory facts revisions <fact-id>
./kindgiw memory facts get <fact-id> --as-of=2026-10-01T00:00:00Z
```

</TabItem>
<TabItem label="Scala">

```sh
./kindgiw memory facts supersede <fact-id> --input='{"content":"Prefers phone"}' --expect-version=1
./kindgiw memory facts verify <fact-id>
./kindgiw memory facts delete <fact-id>
./kindgiw memory facts revisions <fact-id>
./kindgiw memory facts get <fact-id> --as-of=2026-10-01T00:00:00Z
```

</TabItem>
</Tabs>

- **`supersede`** writes the fact's next revision, under the same id.
- **`verify`** marks it verified: a person vouches for it.
- **`delete`** ends it. Its revisions stay until a retention policy on
  `memory` purges them, as
  [Keep and purge deleted data](../../../deploy/retention/) describes.
- **`revisions`** lists them. `get --revision=<n>` and `--as-of=<time>` read
  the past.
- **`<fact-id>`** is the fact's `id`, and `--input` its new content.
- **`--expect-version`** refuses the change if someone changed the fact
  since you read it.
