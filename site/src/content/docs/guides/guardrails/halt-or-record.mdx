A guardrail's action decides what a failed check does to the turn:

- **`halt`** stops it. The turn fails with `guardrail-violation`, and the run
  has no answer.
- **`log-only`** lets it finish. The answer goes out, and the failure is
  recorded on the turn as a violation.

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts
// in guardrails/answer-length/index.ts
action: { 'on-violation': 'log-only' },
```

</TabItem>
<TabItem label="Python">

```python
# in guardrails/answer_length.py
@guardrail(
    id="my-pack.answer-length",
    name="Answer is short",
    on_violation="log-only",
    severity="error",
    config={"maxChars": 60},
)
```

</TabItem>
</Tabs>

## A halted turn

With `halt`, the command fails with the check's reason:

```sh
kindgi runs start --agent=my-pack.echo-agent --input='{"userMessage":"hi"}'
```

```text
Error [guardrail-violation]: Turn blocked by guardrail 'my-pack.answer-length': The answer is 243 characters; the limit is 60.
```

The run is `failed`, and its `failureMessage` carries the violation:

```sh
kindgi runs get <run-id>
```

```json
{
  "id": "5202d750-e510-483f-991a-db34c6cba950",
  …
  "flowId": "agent.turn",
  "status": "failed",
  …
  "failureMessage": "{\"__agent_turn_failure__\":true,\"error\":{\"code\":\"guardrail-violation\",\"message\":\"Turn blocked by guardrail 'my-pack.answer-length': The answer is 243 characters; the limit is 60.\",\"violations\":[{\"guardrailId\":\"my-pack.answer-length\",\"result\":{\"passed\":false,\"reason\":\"The answer is 243 characters; the limit is 60.\"},\"action\":\"halt\",\"severity\":\"error\",\"at\":\"2026-10-03T20:10:37.910Z\"}],\"evaluationErrors\":[]}}"
}
```

Use `halt` for a rule whose failure makes the answer unusable or unsafe to
show.

## A recorded violation

With `log-only`, the turn completes, and its output lists the violation:

```json
  "status": "completed",
  …
  "output": {
    …
    "response": {
      "role": "agent",
      "actor": "my-pack.echo-agent",
      "content": "⚠ dev-echo isn't a real model: it only repeats what it's given. Add an LLM provider key (Anthropic, OpenAI, Gemini, Groq, OpenRouter…) to get real answers.\n\nTool responded: {\"echo\":\"hi\",\"echoedAt\":\"2026-10-07T13:20:06.619Z\",\"characterCount\":2}",
      …
    },
    …
    "violations": [
      {
        "at": "2026-10-03T20:10:57.958Z",
        "action": "log-only",
        "result": {
          "passed": false,
          "reason": "The answer is 243 characters; the limit is 60."
        },
        "severity": "error",
        "guardrailId": "my-pack.answer-length"
      }
    ],
```

Use `log-only` while you find out how often a new rule fails, or for a rule
your app acts on itself: read `violations` from the turn's result.

:::note[Other actions]
The guardrail schema also accepts `retry`, `escalate` and `compensate`. In
0.1 a turn records them as violations, like `log-only`, and doesn't act on
them: there's no second attempt, escalation or compensating tool call.
:::

## When the check can't run

A guardrail whose check can't run at all (no check by that name is
registered, its configuration is invalid, or an `llm-judge` guardrail's judge
can't be routed to a model) never counts as passed:

- With `halt`, the turn fails with `guardrail-violation`. Its `violations`
  is empty, and `evaluationErrors` names the guardrail and says why:
  `Turn blocked: guardrail 'my-pack.answer-length' couldn't run its check (unknown-check: …)`.
- With any other action, the turn completes.

Either way, the error is recorded in the run's provenance (the guardrail's
node, with `evaluated: false`) and in the run journal's `evaluate-guardrails`
step, under `errors`.

## Severity

`severity` is `info`, `warn`, `error` or `critical`. It's recorded with each
violation, and doesn't change what the action does: a `log-only` guardrail
can be `critical`.

## Which agents it covers

A guardrail checks the turns of every agent that lists it. `scope` narrows
that:

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts
// in guardrails/answer-length/index.ts
scope: { when: 'always', agents: ['my-pack.echo-agent'] },
```

</TabItem>
<TabItem label="Python">

```python
# in guardrails/answer_length.py
scope={"when": "always", "agents": ["my-pack.echo-agent"]},
```

</TabItem>
</Tabs>

- `agents` lists the agents the guardrail applies to. An agent that lists
  the guardrail but isn't in its scope isn't checked.
- `when` is `always`, `runtime-only` or `ci-only`. A `ci-only` guardrail
  doesn't run in an agent's turn.
