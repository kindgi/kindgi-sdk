This guide lists the environment variables your pack's code reads, so
`kindgi dev` warns when a required one has no value and a deployment injects exactly
those.

## Before you start

- **A pack** with `kindgi dev`, from Kindgi 0.2's CLI.

## Declare the names

Your tools' code, and the libraries it imports, read settings from the
process environment: a service URL, a database your app owns. The pack
declares which names it reads. Ask your coding agent: "Declare the
environment variables my code reads." Kindgi's skills in your pack tell it
how ([How it knows Kindgi](../../../start/coding-agents/)). For reference, it
adds them to the pack's config like this:

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts excerpt
// in kindgi.config.ts
env: {
  required: ['ORDERS_APP_URL', 'ORDERS_DB_URL'],
  optional: ['ORDERS_API_TIMEOUT_MS'],
},
```

</TabItem>
<TabItem label="Python">

```toml excerpt
# in pyproject.toml
[tool.kindgi.env]
required = ["ORDERS_APP_URL", "ORDERS_DB_URL"]
optional = ["ORDERS_API_TIMEOUT_MS"]
```

</TabItem>
<TabItem label="Java">

```jsonc excerpt
// in kindgi.config.json
"env": {
  "required": ["ORDERS_APP_URL", "ORDERS_DB_URL"],
  "optional": ["ORDERS_API_TIMEOUT_MS"]
}
```

</TabItem>
<TabItem label="Scala">

```jsonc excerpt
// in kindgi.config.json
"env": {
  "required": ["ORDERS_APP_URL", "ORDERS_DB_URL"],
  "optional": ["ORDERS_API_TIMEOUT_MS"]
}
```

</TabItem>
</Tabs>

- **`required`**: names the pack service can't work without.
- **`optional`**: names it reads when they're set.
- Names are environment variable names. `KINDGI_*` names are Kindgi's own
  settings and are refused:

```text
    ✗ refresh failed [config-invalid] kindgi.config: "KINDGI_X" in `env.required`: `KINDGI_*` names configure Kindgi, not the pack
```

Your code reads them as usual: `process.env.ORDERS_APP_URL`,
`os.environ["ORDERS_APP_URL"]`, `System.getenv("ORDERS_APP_URL")` in Java, or
`sys.env("ORDERS_APP_URL")` in Scala. The `order-link` tool in
[Keep local values in env files](../env-files/#what-reads-them) reads one.

## On your machine

`kindgi dev` gives the pack service the env files' values, and warns about
a required name that has none:

```text
    ⚠ the pack's env.required name ORDERS_DB_URL has no value: add it to the pack's env files (a deployment won't be ready without it)
```

It warns and carries on, so the rest of the pack keeps working while you
fill it in. `kindgi dev` doesn't reload on a change to a TypeScript pack's
`kindgi.config.ts` or a Java or Scala pack's `kindgi.config.json`: save a tool
or restart it. A Python pack reloads when `pyproject.toml` changes.

## In a deployment

:::note[On Kindgi Cloud]
The pack service gets the values of the names its pack declares, plain or
secret, as your workspace sets them for `prod`, the env Kindgi Cloud serves:
at the deployment's project, then its org, then the tenant. Set a plain value
with `kindgi env set NAME <value> --scope=project:<projectId> --env=prod`, or
with `--scope=org:<orgId>` or `--scope=tenant`
([Give a tool per-project values](../../tools/give-a-tool-env-values/)), and a
secret with `kindgi secrets set NAME --scope=project:<projectId> --env=prod`
([Give a tool a secret](../../tools/give-a-tool-a-secret/)), not in the pack's
config: `kindgi deploy --hosted` refuses an `env` there for the environment it
deploys to. The audit record has a row each time the pack service is given a
secret, never its value. When a value changes, Kindgi starts the pack service
again with it, with no deploy.

The pack service isn't started, or one that's running keeps the values it
has, while a required name is set nowhere (`pack-env-missing`), a name is set
both as a secret and as a plain value (`pack-env-ambiguous`), or a secret's
value is over 32 KiB (`pack-env-secret-too-large`). The deployment shows the
code. The same holds while a secret can't be read or given for a reason
Kindgi fixes (`pack-env-secret-unreadable`, `pack-env-secrets-unaudited`,
`pack-env-secret-capacity`): Kindgi's team is told, and it's tried again. A
running pack service that can't be given a name that's newly set only as a
secret keeps the values it has (`pack-env-secret-redeploy`). Build the pack
again and deploy that build into the same project, with
`kindgi build --hosted --env=prod` and then
`kindgi deploy --hosted --env=prod --project=<projectId>` (leave `--project`
out for the Default project): the new deployment's pack service can be given
it.
:::

Where a pack service is run for each deployment, as on Kindgi Cloud,
`kindgi deployments get <deployment-id>` shows it after the deploy: whether
it's ready, and when it runs on the values it was last given, why, since
when, and the command that sets what's missing.
`kindgi deployments list --table` lists the deployments, with their ids.

The declaration is part of the pack's index, so the pack service in an image
knows what it needs:

- **Only declared names are injected.** The pack service gets each declared
  name that has a value for that environment, and nothing else.
  [Set values per environment](../per-environment-values/) shows where those
  values come from, and `kindgi env plan` says when one isn't declared:
  `environments.staging.env.FEATURE_FLAGS isn't declared in env.required or env.optional, so it isn't injected`.
- **The pack service keeps only the declared names.** However it's started,
  such as with `docker run --env-file` or a Terraform input with a key added
  by hand, it removes every other variable from its environment before your
  code loads. So a model key or a password meant for something else never
  reaches a tool, or a process a tool starts. Kindgi's own `KINDGI_*`
  settings and the platform's stay: the process's basics, the language runtime's
  settings, `PORT`, proxies and certificates, and Cloud Run's, AWS's and
  Azure's workload identity and metadata. A static credential such as
  `AWS_SECRET_ACCESS_KEY` isn't the platform's: declare it if your code reads
  it. The service names what it removed, never a value:

  ```json
  {"time":"2026-10-10T07:01:47.789Z","level":"warn","severity":"WARNING","subsystem":"pack","message":"Dropped 2 variables the pack doesn't declare: ACME_UNDECLARED_KEY, AWS_SECRET_ACCESS_KEY (declare them in the pack's env, or set KINDGI_PACK_ENV_FILTER=off)","event":"env-dropped","kind":"env-dropped","names":["ACME_UNDECLARED_KEY","AWS_SECRET_ACCESS_KEY"]}
  ```

  A Python pack's image always names `GPG_KEY` there: its base image sets
  it, and nothing reads it. `KINDGI_PACK_ENV_FILTER=off` on the pack service
  keeps every variable. `kindgi dev` runs with it off, since there the pack
  service gets your env files. The
  [environment variable reference](../../../reference/env-vars/#kindgi_pack_env_filter)
  has the setting.
- **A required name with no value keeps the pack service from serving.** It
  starts, says which names are missing, and answers `503` until they're set:

```text
{"kind":"missing-env","check":"strict","names":["ORDERS_DB_URL"]}
```

```json
{"error":"missing env","missingEnv":["ORDERS_DB_URL"]}
```

`KINDGI_PACK_ENV_CHECK=warn` on the pack service makes it serve anyway and
only report the names, as `kindgi dev` does. The
[environment variable reference](../../../reference/env-vars/#kindgi_pack_env_check)
has the setting.

## What doesn't go here

A secret that belongs to a tenant, such as an API key a customer gives you,
isn't part of the pack's environment: one pack service serves every tenant.
A tool declares it and reads it from its context, as
[Give a tool a secret](../../tools/give-a-tool-a-secret/) shows.
