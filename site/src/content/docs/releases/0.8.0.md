Released November 16, 2026. For the docs of this version, see
[docs.kindgi.com/v0.8.0](https://docs.kindgi.com/v0.8.0/).

## New

- **HubSpot and Asana connect, and agents use their own MCP servers'
  tools.** You register your company's HubSpot MCP connector or Asana MCP
  app with Kindgi once. Then each person connects their own HubSpot or
  Asana user, and a tenant admin can connect the company's.
  `kindgi mcp add hubspot` or `kindgi mcp add asana` registers the vendor's
  server at the runtime, and each call of its tools runs as the person the
  run acts for, or, with `--as=company`, as the company.
  [HubSpot](../../guides/connections/hubspot/),
  [Asana](../../guides/connections/asana/).

- **An MCP endpoint can sign in as a connection.** Its `auth` takes
  `{ scheme: 'connection', app, as: 'person' | 'company', permissions? }`,
  and `catalogConnectionId` names the connection its tools are listed
  with: your own, or the company's. Each call sends the token of its own
  connection. A call whose connection isn't the kind `as` names is refused
  with `mcp-auth-unresolved`. A `401` renews the token once and runs the
  call again, and a `429` is the call's `mcp-rate-limited`, with the wait
  the server asks for. The resources and prompts reads refuse such an
  endpoint, since a read carries no caller's connection.
  [Sign in as a connection](../../guides/tools/mcp-servers/#sign-in-as-a-connection).

- **A connection's token goes only to its app's MCP servers.** An app's
  entry lists its servers, and an endpoint with a URL on none of their
  origins is refused. When the endpoint is registered, Kindgi reads the
  server's Protected Resource Metadata (RFC 9728), and refuses it unless
  its `resource` is the entry's, exactly, and its `authorization_servers`
  names the entry's issuer: `400 invalid-mcp-endpoint`, with the reason
  `resource-mismatch`, `issuer-mismatch` or `resource-metadata-unreadable`.
  Each token is minted for the server's resource (RFC 8707). No token
  appears in an error, a log or a journal record.

- **An app entry you write can have its own MCP server.** `defineApp`
  takes `mcpServers`, each `{ origin, resource, issuer }`.
  `signIn.scopesFrom: 'registration'` asks for no scope, and
  `account: { kind: 'none' }` reads no account: each person, and the
  company, has one connection per app and env, and connecting again renews
  it.
  [An app with its own MCP server](../../guides/connections/add-an-app/#an-app-with-its-own-mcp-server).

## Fixed

- **`KINDGI_ACCOUNT_KEY`'s description says what's so.** It said runtime
  0.7.0 used it for connections through a Meta app. No runtime release
  reads it, so setting it changes nothing.

## Changed

- **The deprecated `artifacts` names and the old version calls are
  removed in 0.9.0, not 0.8.0.** `/v1/artifacts`, `client.artifacts`,
  `kindgi artifacts`, `KINDGI_ARTIFACTS` and `KINDGI_ARTIFACT_MAX_BYTES`
  work in 0.8.0 as they did in 0.7.0, deprecated, and so do the old names
  of the policies', schedules', webhooks', mail triggers', queue rules' and
  secrets' version calls. The 0.7.0 notes said 0.8.0 removes them. Each
  deprecation notice now names 0.9.0.
  [What 0.9.0 removes](../../concepts/files-and-versions/#what-090-removes).

## Known issues

- **A new Java or Scala pack can't resolve kindgi-pack 0.8.0 yet.** The JVM
  SDKs reach Maven Central at 0.8.0 later: until then, a Java or Scala pack
  the CLI scaffolds can't resolve it. The packages on npm (`@kindgi/*`) and
  PyPI (`kindgi`, `kindgi-cli`) are at 0.8.0 now.

- **Runtime 0.8.0 can't be handed a renewed license key while it runs.** It
  doesn't serve `PUT /v1/license`, so `license.replace` can't hand it one,
  and `kindgi license renew --runtime` writes the key with a warning that
  the runtime uses it from its next start. On Cloud Run, that's when an
  instance next starts.

- **Disconnecting HubSpot or Asana withdraws nothing at the vendor.** The
  stored token is destroyed, and the access token Kindgi last had works
  until it expires. What the person allowed stays allowed until they
  remove the app at HubSpot or Asana.

## Upgrade steps

- **From 0.6.x, follow 0.7.0's Upgrade steps first**
  ([Kindgi 0.7.0](../0.7.0/#upgrade-steps)).

- **The upgrade adds no migrations.** An endpoint that signs in as a
  connection is kept the way every endpoint is.

- **To use HubSpot or Asana, upgrade the runtime and the CLI together.**
  Runtime 0.7.0 refuses a `connection` auth as `invalid-auth`, and
  `catalogConnectionId` as `unknown-field`, and registers nothing.

- **A server whose egress you limit needs to reach the vendor.** For
  HubSpot, `mcp.hubspot.com`; for Asana, `mcp.asana.com` and
  `app.asana.com`.

- **Move off the deprecated `artifacts` names and the old version calls
  before 0.9.0.** Each one's deprecation notice names its replacement
  ([What 0.9.0 removes](../../concepts/files-and-versions/#what-090-removes)).
