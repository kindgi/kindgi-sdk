Released November 16, 2026. For the docs of this version, see
[docs.kindgi.com/v0.8.1](https://docs.kindgi.com/v0.8.1/).

## Fixed

- **An Anthropic provider can send its calls through a gateway or a
  proxy.** `@kindgi/adapter-model-anthropic` takes one `adapter_config`
  key, `baseURL`: an https URL of a gateway or a proxy that serves the
  Anthropic API. The provider's calls then go there, with the key its
  `secret_ref` names. An http URL is taken only on this machine
  (`localhost`, `127.0.0.1`, `[::1]`, `host.docker.internal` or
  `host.containers.internal`), for a gateway run locally. A URL with
  credentials, a query or a fragment is refused, naming the problem.
  Before, the adapter took no `adapter_config`, so a registration that
  named a base URL was refused. `kindgi dev` runs runtime 0.8.1.
  [Through a gateway or a proxy](../../guides/models/anthropic/#through-a-gateway-or-a-proxy).

## Known issues

- **0.8.0's known issues hold in 0.8.1.** A new Java or Scala pack can't
  resolve kindgi-pack 0.8.1 yet, a running runtime can't be handed a
  renewed license key, and disconnecting HubSpot or Asana withdraws
  nothing at the vendor ([Kindgi 0.8.0](../0.8.0/#known-issues)).

## Upgrade steps

- **From 0.7.x, follow 0.8.0's Upgrade steps first**
  ([Kindgi 0.8.0](../0.8.0/#upgrade-steps)).

- **The upgrade adds no migrations.**

- **To send an Anthropic provider's calls through a gateway, upgrade the
  runtime first, then register the provider with the URL.** Runtime 0.8.0
  refuses `adapter_config.baseURL`. The URL goes in `adapter_config`, never
  in `metadata`, which takes only `id`, `region`, `models` and
  `defaultModel`.
