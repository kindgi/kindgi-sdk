Released November 15, 2026. For the docs of this version, see
[docs.kindgi.com/v0.7.0](https://docs.kindgi.com/v0.7.0/).

## New

- **A tool can fail a call on purpose, with its own code and words.**
  `` throw new ToolFailure('order-not-found', `No order ${orderId}`, { details: { orderId } }) ``
  from `@kindgi/sdk/define` fails the call with `tool-failed` (`ToolFailure`
  in Python, `ToolFailureException` in Java and Scala). The code, kebab case
  and at most 64 characters, is the `reason`; the details, a JSON object of
  at most 4 KiB, go to the run's `failure`. An agent whose
  `toolErrors.retryOn` names `tool-failed` hands them to its model. It's
  pack protocol 2.12.0.
  [Fail a call on purpose](../../guides/tools/write-a-tool/#fail-a-call-on-purpose).

- **Files keep every version, under `/v1/files`.** `/v1/files` lists,
  creates, reads and deletes files, and adds, downloads, restores, pins and
  deletes their versions, by number or `latest`. Adding or restoring one
  takes `expectedVersion`; a stale one answers `409 file-version-conflict`.
  The clients have `client.files` (`client.files()` in Java), the CLI
  `kindgi files`, and an export carries files with their versions.
  [Files and versions](../../concepts/files-and-versions/).

- **A tool, or an agent's model, can add a version to a file.** A tool that
  declares `updatesFiles: true` (`updates_files=True` in Python) gets
  `ctx.files.update(...)`, which answers `file`, `same`, `conflict` or
  `notUpdated`. An agent that declares `files: { update?, create? }` offers
  its model the built-in `kindgi_update_file` and `kindgi_create_file`. An
  update is at most 10 MB. It's pack protocol 2.13.0 and agent schema 1.9.0.

- **A run can start from a text message, and an agent can answer it.** A
  text trigger starts a run for each text, SMS or WhatsApp, to a business
  number. Connect it with
  `kindgi connection-apps add texts --provider=telnyx` and
  `kindgi connections connect texts --for-company --number=<E.164>`, then
  register triggers under `/v1/text-triggers`. `runsPerHour` (60) and
  `perSenderPerHour` (10) limit the runs. Each tool that changes something
  waits for a person's yes unless `toolsAllowedUnattended` lists it. The
  agent answers with `kindgi_reply_to_text`, or hands over with
  `kindgi_hand_to_person`. [Texts](../../guides/connections/texts/).

- **A schedule can send its results to its owner's email or to a
  destination.** A workspace admin sets up destinations under
  `/v1/destinations`: `email`, `slack`, `teams`, `google-chat`, `discord` or
  `webhook`. A schedule's `sendResultsTo` holds up to five `{ to, on }`:
  `to` is a destination or `me`, `on` any of `completed`, `failed`,
  `cancelled` and `waiting`. `GET /v1/schedules/{triggerId}/deliveries`
  lists where its results went.
  [Send results to a destination](../../guides/runs/send-results-to-a-destination/).

- **A tool answers dates and times in the workspace's time zone.** The
  workspace's `time-zone` fact reaches every call of an agent turn as
  `ToolContext.timeZone`, such as `America/Toronto` (`time_zone` in Python,
  `timeZone()` in Java and Scala), and `UTC` when it sets none. Outside an
  agent turn it's absent, so a tool uses UTC.
  [Answer in the workspace's time zone](../../guides/tools/write-a-tool/#answer-in-the-workspaces-time-zone).

- **Agents can find and add files in Google Drive, OneDrive and
  SharePoint.** `googleDriveFilesList`, `googleDriveFileGet` and
  `googleDriveFileCreate` need `drive.readonly`, `drive.file` and the Google
  Drive API on. `oneDriveFilesList`, `oneDriveSharedFilesList`,
  `sharePointLibrariesList` and `oneDriveFileCreate` need `Files.Read`,
  `Files.ReadWrite`, `Files.Read.All` and `Sites.Read.All`, the last two
  with an admin's consent. An older connection lacks them until the person
  allows them.
  [Files in Drive and OneDrive](../../guides/connections/files/).

- **A LinkedIn post can carry images or a link card, and can be deleted.**
  `linkedinPost` takes `images`, 1 to 20 of the run's files, each with its
  `altText`, and `link`. `linkedinDeletePost` deletes a post, and in a run
  no person started waits for the person's yes.
  [LinkedIn](../../guides/connections/linkedin/).

- **An API key can be made to only read.** `POST /v1/tokens` with
  `readOnly: true` makes a key whose every request but a `GET` or a `HEAD`
  is refused with `403 read-only-key`. It makes and revokes no keys. Python
  takes `read_only`, and Java's `MintTokenBody` `readOnly`.
  [A key that only reads](../../deploy/people-and-keys/#a-key-that-only-reads).

- **People at a workspace's email domain can join it.** Someone who signs
  in with a mailbox at an allowed domain, proved by a Google Workspace
  account, a Microsoft work account or the emailed link (never GitHub),
  joins as `viewer`, `runner` or `none`, never tenant admin. A tenant admin
  allows their own domain with `POST /v1/auth/join-domains`, from a sign-in
  that proved an email there (else `403 join-domain-not-yours`), and the
  operator with `kindgi sign-in join-domains allow`; a public mailbox domain
  is refused. With `KINDGI_AUTH_TENANT_PROVIDERS=off`, allowing a domain is
  the operator's (`403 join-domains-operator-managed`); `system:join-domains`
  and `system:join-domains:read` cover the operator's routes and a sign-up
  page's lookup. An identity provider's `join: domain` now lets colleagues
  in too, with `joinRole`. Both need the authorization store
  (`409 domain-join-needs-authorization`). A person's record gains
  `createdBy`.
  [Let people at your domain join](../../deploy/people-and-keys/#let-people-at-your-domain-join).

- **A self-hosted workspace's tenant admins can be named by email.** On a
  runtime that serves one workspace and has an authorization store, each
  address in `KINDGI_ADMIN_EMAILS` is a tenant admin from its first sign-in,
  and taking that away is refused with `409 listed-admin`.
  [Tenant admins by email](../../deploy/people-and-keys/#tenant-admins-by-email).

- **A tenant admin can give another tenant admin capabilities, and take them
  back.** The clients' `users.giveCapabilities` gives them, and
  `users.takeBackCapability` takes one back.
  [Give a tenant admin capabilities](../../deploy/people-and-keys/#give-a-tenant-admin-capabilities).

- **A deleted project is kept, and a workspace admin can restore it.**
  `POST /v1/projects/{projectId}/restore` brings one back as it was, and
  `GET /v1/projects/deleted` lists the deleted ones (`projects.restore`,
  `projects.listDeleted`). A webhook delivery to a deleted project answers
  `skipped: 'project-deleted'`, and the default project can't be deleted
  (`409 project-is-default`).
  [Delete and restore a project](../../guides/projects/organize-by-org-and-project/#delete-and-restore-a-project).

- **A build can be promote-only.** It reaches production only by promotion
  when its signed envelope says `productionEntry: 'promote-only'`, or its
  signing key's id starts with `kindgi-promote-only:`. A deploy of one
  answers `409 promote-only-build`.

- **The runs list can say what each waiting run waits for.**
  `GET /v1/runs?include=waitingFor` gives each suspended run its
  `waitingFor`, at most 25 runs a page; `include=output,waitingFor` asks for
  both. The comma form works on an agent's test cases, the cost records and
  the people list too. The TypeScript client takes `includeWaitingFor`.
  [List runs](../../guides/runs/list-runs/).

- **A removed trigger can still be read, and an unregister says what runs a
  version.** Triggers take `?includeUnregistered=true` for removed ones,
  with `unregisteredAt`. Unregistering a tool or agent version answers
  `lockedBy`: each agent and flow version you can read that runs it.

- **An MCP endpoint's registration can name the server's tools that only
  read.** `readOnlyTools` lists up to 256 of them by name. A listed tool
  runs in a dry run and passes an approval gate with no rule for it. The
  server's own `readOnlyHint` isn't read: the list is the registrant's
  claim. It needs runtime 0.7.0.
  [Name its read-only tools](../../guides/tools/mcp-servers/#name-its-read-only-tools).

- **A connection entry can say it signs in through Kindgi's own app.** In
  the API, an entry's `signIn.kind` can be `kindgi-app`: it connects through
  Kindgi's own app, by Kindgi's connect step, with no client of your own to
  register, and its registration's `via` is `kindgi`. No app 0.7.0 ships
  signs in this way yet: its apps are Google, GitHub, Microsoft, LinkedIn
  and texts.

- **`kindgi dev` offers connections.** An agent or a flow can use your own
  app at a provider on your laptop. `kindgi dev` keeps the tokens in its
  database, encrypted under a key pair only you can read, and its start
  names the redirect URI to register,
  `http://127.0.0.1:4000/console/connect/callback`.

- **The CLI signs in to hosted Kindgi, and keeps a login per profile.**
  `kindgi auth login --hosted` signs in to `https://platform.kindgi.com`.
  `--profile` or `KINDGI_PROFILE` picks a login, and `kindgi auth list` and
  `kindgi auth logout` show and remove them.

- **A license key can set when it warns and what it limits.** A key's
  `warn`, 1 to 30 days, sets when it starts warning. A production key's
  `lim` sets its plan for flows and agents, which `GET /v1/license` shows
  the operator as `limits`. A key signed with `lk-2026-l1` verifies on
  runtime 0.7.0 or later. The clients' `license.replace` (`PUT /v1/license`)
  hands a renewed key to a running server that takes one, which runtime
  0.7.0 doesn't (Known issues).
  [Renew the license key](../../deploy/self-hosted/renew-the-license-key/).

- **The runtime reports its use once a day.** From 0.7.0, it sends a daily
  license report to `KINDGI_LICENSE_REPORT_URL`,
  `https://access.kindgi.com/v1/report` by default (Upgrade steps).
  [What the runtime sends](../../deploy/self-hosted/what-the-runtime-sends/).

- **The Cloud Run module can renew the license key on a schedule.** With
  `license_renewal_schedule`, a Cloud Run job runs `kindgi license renew`
  and never restarts the server; with `license_usage_key_secret`, it sends
  the deployment's counts too.
  [8. Renew the license key](../../deploy/self-hosted/cloud-run/#8-renew-the-license-key).

- **A runtime can count the flows and agents in production against its key's
  plan.** At the plan, a write's answer carries `planWarning`; past the most
  the key runs, a write that adds new ones is refused with
  `403 plan-limit-reached`. A tenant can have its own limits,
  `flowsInProduction` and `agentsInProduction`. Without a plan limits
  binding, nothing is counted.
  [Plan limits](../../deploy/self-hosted/plan-limits/).

- **A deployment can limit what people upload for their runs.** Someone who
  may run a project but not write to it uploads at most 1 GiB and 1,000
  files a day by default (`KINDGI_RUN_UPLOAD_DAILY_BYTES`,
  `KINDGI_RUN_UPLOAD_DAILY_FILES`), then gets `429 upload-limit-reached`. An
  upload marked `forRun=true` is deleted when no run names it within 24
  hours. A put past `TenantLimits.storageMiB` is refused with
  `403 storage-limit-reached`.
  [Keep files with a run](../../guides/runs/keep-files-with-a-run/).

- **New runtime settings for self-hosted operators.**
  `KINDGI_TENANT_EGRESS_PROXY` and `KINDGI_TENANT_EGRESS_NO_PROXY` send
  connections and webhooks through a forward proxy. `KINDGI_DB_POOL_SIZE`
  sets the database pool per server process, 10 by default.
  `KINDGI_TICK_CALLER` and `KINDGI_SERVICE_URL` let a server scale to zero.
  A runtime serving many tenants can run each tenant's pack services as its
  own account (`KINDGI_ORCHESTRATOR_TENANT_ACCOUNTS`), and keep a git repo
  per project without GitHub (`KINDGI_KEPT_REPOS`).
  [Scale the server to zero](../../deploy/self-hosted/cloud-run/#scale-the-server-to-zero).

- **Sign-in gains a sign-up link and SAML certificates.**
  `GET /v1/auth/sign-in-options` gains `signUpUrl`, set with
  `KINDGI_AUTH_SIGN_UP_URL`, for a "No account yet? Sign up" link. A SAML
  provider's `spSigningCertificates` and `spDecryptionCertificates` go into
  the service provider's metadata.
  [A sign-up link](../../deploy/self-hosted/sign-in/#a-sign-up-link).

- **`@kindgi/api/run-result` gives one way to draw a run's result.** A
  browser bundle can import it: `RUN_STATUS_WORDS`, `answerValue`,
  `answerBlocks` and `clipText`. In a chat, a run tool's result carries the
  answer's blocks in `_meta["kindgi/blocks"]`.

- **Python, Java and Scala packs can name a built-in check as a guardrail.**
  `built_in_guardrail(...)` in Python and `builtInCheck(checkId, config)` in
  Java and Scala, as a TypeScript pack does.
  [Use a built-in check](../../guides/guardrails/use-a-built-in-check/).

## Fixed

- **Your app's own Jackson reads every Java SDK model.** An agent, a test
  run's baseline, an agent's instructions and a secret rotation's answer now
  read with your app's own Jackson, as every other model does. This was a
  known issue in 0.6.0.

- **A network error says what caused it, and keeps secrets out.** The
  Anthropic, OpenAI-compatible, Azure OpenAI and Bedrock adapters say the
  causes, such as `Cannot connect to API; caused by ...`. A Java or Python
  tool's or check's error says them too, with the call's secrets and tokens
  as `[redacted]`.

- **The `gemini` and `gemini-api` presets price a cached token at a tenth.**
  It was a quarter, 2.5 times too high. A provider you registered from them
  keeps the old prices: unregister it and register the preset again.
  `kindgi dev` does that on its next start.

- **Guardrails run as configured.** A guardrail listed twice runs once, so
  an llm-judge is billed once. A guardrail with `sees: 'conversation'` now
  gets the earlier turns in `trace.earlier`, which was never filled. What a
  judge's model call warns about comes back in `CheckResult.warnings`.

- **An agent turn keeps its work when it's resumed.** `resumeAgentTurn`
  takes an `abortSignal`, so an agent step that times out stops its turn. A
  turn resumed after its worker was lost keeps its instructions, where it
  failed with `model-invocation-failed`. Typed output no longer fails early
  with `output-schema-violation`.

- **Approval rules are in the OpenAPI document and the agent spec.**
  `conversationPolicy.hitl` is in agent spec 1.8.0, and the Java and Python
  clients take it. A rejected approval's result says `rejected`, `by` and
  the `rationale`.

- **Keys limited to a project act in it, without an authorization store.**
  Such a key reads `GET /v1/projects/default` when that's its project, and a
  run or a conversation it starts with no project lands in its project.
  Acting by id in another project answers `403 key-project-mismatch`.

- **A deployment's checks read what it recorded.** Its values check reads
  secrets at the scope it recorded, and a revoked model key reads `revoked`.
  A deployment that fails after its first write tells the tool and guardrail
  caches what it undid.

- **A mail's text can't pass for a mail turn's own lines.** `mailTurn` sets
  in, by one space, every line of a mail that would read as one of the
  turn's own, such as one starting `To:`, `Cc:` or `Attachments:`, as a
  `---` line already was.

- **A Java waited start that times out isn't sent again.** It threw a
  `ConflictException`, and the run's id never arrived. It now throws a
  `NetworkException` that says the run may still be going.

- **The TypeScript `projects.update`, `orgs.update` and `teams.update`
  resolve to nothing.** Their routes answer `204 No Content`, so they always
  resolved to `undefined`. They now return `Promise<void>`, so code that
  read a field off the result no longer compiles: read the record with
  `get`.

- **Python and Java packs refuse at definition what a deploy refused.**
  Python's `http_tool` raises `DefinitionError` for a placeholder in the
  URL's host or port, and a tool schema whose property name holds a lone
  surrogate is refused in Java, Scala and Python.

- **Model adapters keep to what's registered.** The in-process adapter keeps
  to a model's registered `maxOutputTokens`, and the OpenAI-compatible
  adapter no longer fails with `ERR_MODULE_NOT_FOUND`. A turn that merges
  two policies keeps the larger `maxTokensPerCall`.

- **An upload that will be refused isn't read first.** A workspace past its
  API requests a minute, or closing or suspended, is refused before an
  upload's body is read.

- **Smaller fixes.** With `HOME` set but empty, the CLI refuses rather than
  use a folder under the current one. A TypeScript pack skips `_` helper
  modules, such as `tools/_shared.ts`, that define nothing. A pack service
  no longer warns about `GPG_KEY` at every start. Finding links and masking
  secrets in long text no longer stall. A `kindgi dev` providers record from
  before 0.6.0, keyed on a hash, is left as it is:
  `kindgi providers unregister <id>`, then a restart, fixes it.

## Changed

- **`kindgi dev` needs a license key.** Every runtime runs with a license
  key from 0.7.0, and the free non-production key from access.kindgi.com
  covers development. `kindgi auth registry` keeps it in
  `~/.kindgi/license/license-key`; `kindgi dev` takes `KINDGI_LICENSE_KEY`,
  else that file, and with neither stops before anything starts. When your
  key renews, run `kindgi auth registry` again.
  [Building is free](../../concepts/licensing/#building-is-free).

- **Breaking: a key limited to a project, with authorization on, acts only
  in its project.** It no longer reads the workspace's rows with no project,
  such as cost records and approvals, or its settings, so
  `kindgi providers list|get` and `kindgi sso providers list|get` refuse it.
  It doesn't list or revoke its person's sessions, reads only the
  connections its runs may use, changes none, and writes memory only in its
  project (`403 permission-denied`). Use a key with no project for the rest.

- **A key limited to a project can't hold `kindgi:system`.** Making one is
  refused with `403 capability-not-mintable`. One made before loses the
  operator's view (warning `system-capability-dropped`): revoke it and make
  one with no project.

- **A trigger a project-limited key registers goes in the key's project.** A
  schedule, webhook or mail trigger with no `projectId` lands in the key's
  project, not the default one.

- **A pack's `pack.version` must be `MAJOR.MINOR.PATCH`, such as `1.0.0`.**
  A `pack.version` of `"1"`, `"1.0"` or `"1.0.0-rc.1"` no longer loads:
  `kindgi build`, `deploy`, `dev` and the rest stop with
  `config-parse-failed`. A Java, Scala or Python tool with no version of its
  own takes the pack's.

- **A Python, Java or Scala pack's flows are checked as TypeScript ones
  are.** A cycle or a missing edge fails `kindgi dev` and `kindgi build`
  with `manifest-validation-failed`, and a deploy refuses it with
  `deployment-validation-failed`.

- **A Python pack's image build fails when a module won't import.** It used
  to leave that module's tools out. A package that only a dev group lists
  belongs in `[project].dependencies`.
  `python -m kindgi.pack index --strict` exits 1 on such a file.

- **`createClient()` takes the URL and token from `kindgi dev` together, or
  not at all.** With `KINDGI_API_TOKEN` set and no URL, it no longer sends
  that token to the URL in the nearest `.kindgirc.json`: it throws, naming
  what to set. The Java client throws `IllegalStateException`, the Python
  client `ValueError`. Set both, or neither.

- **An HTTP tool's `secretRef` can leave its env out.** The secret is then
  read in the env the runtime serves (`KINDGI_ENV`; `local` under
  `kindgi dev`). Breaking for code that reads a ref's env:
  `ToolSecretRef.envName` is `string | undefined`, so write
  `store.get(ref.envName ?? env, ref.name)`.

- **The run stream's kinds list only what it sends.** Eight kinds it never
  sent, such as `run.queued`, `run.model-token` and
  `run.approval-requested`, are gone from `run-event.schema.json` 1.1.0 and
  the TypeScript, Python and Java types. TypeScript code that names one
  stops compiling: remove the case.

- **A release gate's resolve needs `scopeKind`.** `scope_kind` is required
  in Python, and the Java overload without parameters is gone. Pass the
  scope kind you resolve for.

- **A flow's agent step that names its version is checked when the flow is
  published.** A `config.version` that doesn't exist, or that the flow's
  project doesn't run, is refused with `400 reference-out-of-scope` on
  publish, reinstate and deploy, where the flow's first run failed at that
  step.

- **`artifacts` is deprecated, and 0.8.0 removes it: use `files`.**
  `/v1/artifacts`, `client.artifacts` and `kindgi artifacts` still work,
  each naming its replacement. An id an upload answered is its file's id in
  `client.files` too. `KINDGI_ARTIFACTS` and `KINDGI_ARTIFACT_MAX_BYTES`
  become `KINDGI_FILES` and `KINDGI_FILE_MAX_BYTES` in 0.8.0.
  [What 0.8.0 removes](../../concepts/files-and-versions/#what-080-removes).

- **Every resource's version calls live under `versions`.** Policies,
  schedules, webhooks, mail triggers, queue rules and secrets get
  `versions.list`, `versions.get`, `versions.unregister` and
  `versions.reinstate`. Their old names work, deprecated, until 0.8.0. Older
  deprecated calls, such as `tools.listVersions`, go in a later minor
  release, announced in advance.

- **`client.capabilities.providers` is deprecated: use `client.providers`.**
  Its methods now call `client.providers`'s, so `configure`, which the API
  always refused, now registers. `configure` is `providers.register`, and
  `delete` is `providers.unregister`.

- **Removing a person removes their connections.** Each goes as a disconnect
  does, and a connection's `removedReason` gains `owner-removed`.
  [Remove a person](../../deploy/people-and-keys/#remove-a-person).

- **An identity provider's secret is its sign-in's alone.** An OIDC client
  secret or SAML key an identity provider references is refused to any other
  use, such as a tool or a pack's `env`
  (`400 identity-provider-key-refused`), and a provider can't reference a
  secret another use holds (`409 identity-provider-key-in-use`). A texts
  account's key is refused to a pack's `env` too. Give each app registration
  its own client secret.

- **A key can't outlive the key that made it.** When an admin's key is
  revoked, or the admin removed, the keys they made with it from the command
  line stop too, pipelines' keys included. The revoke answers `alsoRevoked`,
  and `GET /v1/tokens?mintedWith=<tokenId>` lists the keys made with a key.

- **A project's admins can't give, change or take away `owner`.** That takes
  `delete` on the project; anyone else gets `403 permission-denied`. A
  custom `TenantHierarchyBinding` must honor `stopAtOwner`.

- **A busy store answers `503` with `Retry-After`, where sending again is
  safe.** An unreachable authorization store answers
  `503 authz-backend-unavailable`, and a database too busy for a read before
  the handler `503 database-busy`, each with `Retry-After: 5`, where they
  answered 500.

- **A Gemini network failure throws `ModelProviderError`.** It has
  `kind: 'network'` and no status. Code that checked for a `TypeError` or
  `fetch failed` checks its `cause`.

- **The workspace's config asks for admin rights, and its writes are
  audited.** `GET /v1/tenant/config` needs admin on the workspace, and
  `PATCH /v1/tenant/config` asks `secrets:write` or `env:write` for what it
  writes. Each write is in the audit log, never with its value. A new secret
  another writer made at the same moment is now stored as the key's next
  version, where its value was lost.

- **A chat app's request to `/mcp` counts once toward API requests a
  minute.** The `/v1` requests its tools make count on it, up to 40 a
  message. An MCP endpoint refuses MCP's own `Mcp-` headers in
  `config.headers` (`transport-header-in-config`) and in `auth.headers`.

- **The templates' agents and flows are named for what they do.** A new pack
  from the sample, Python, Java or Scala template has `<pack>.greeter` and
  `<pack>.greet-person`. A pack you made keeps its ids; `kindgi dev` and
  `kindgi build` warn on one that isn't `<pack-id>.<name>`.

- **A zod 3 schema is refused by name.** The words say Kindgi takes zod 4
  schemas, and show the JSON Schema object to write instead. Move the app to
  zod 4, or write JSON Schema.

- **The coding agent's deny rules cover `db.env` and `openfga.env`.** A
  project you made before needs the two lines added.

- **For code built on Kindgi's packages.** A tool that embeds the CLI passes
  `progress` to `runCli`: `connectionsSeam.progress` and
  `exportsSeam.progress` are gone. `startCronScheduler` is deprecated:
  register a `cron` trigger with `TriggerRegistryBinding.register`. A custom
  platform binding's project `delete` answers `changed`.

## Known issues

- **A new Java or Scala pack can't resolve kindgi-pack 0.7.0 yet.** The JVM
  SDKs reach Maven Central at 0.7.0 later: until then, a Java or Scala pack
  the CLI scaffolds can't resolve it. The packages on npm (`@kindgi/*`) and
  PyPI (`kindgi`, `kindgi-cli`) are at 0.7.0 now.

- **Runtime 0.7.0 can't be handed a renewed license key while it runs.** It
  doesn't serve `PUT /v1/license`, so `license.replace` can't hand it one,
  and `kindgi license renew --runtime` writes the key with a warning that
  the runtime uses it from its next start. On Cloud Run, that's when an
  instance next starts.

## Upgrade steps

- **From 0.5.x, follow 0.6.0's Upgrade steps first**
  ([Kindgi 0.6.0](../0.6.0/#upgrade-steps)).

- **Before you upgrade, run the new image's `identity-provider-keys`
  check.** An identity provider's secret is now sign-in's only, so a tool,
  an endpoint, a trigger, a connection app registration, a model provider
  or a pack's `env` that names one is refused it after the upgrade. The
  check lists each of them on the database you're about to upgrade. For
  each, store the secret it needs under its own name (the same value is
  fine), name that instead, and deploy or register it again.
  `check provider-keys` now also lists webhook triggers and connection app
  registrations. On Cloud Run and Azure Container Apps, `upgrade.sh` runs
  both
  ([Checks you can run before upgrading](../../deploy/self-hosted/operate/#checks-you-can-run-before-upgrading)).

- **The upgrade's migrations fill nothing in.** They add the tables and
  columns this release's features keep: destinations, file versions,
  texts, joining a workspace by email domain, the license's state and plan
  limits. The first start also builds two new indexes on the runs table
  without blocking writes, and the log names each one,
  `[migrations] building index <index> on <table>; writes go on, and a large table takes a while`,
  then `built index <index> in <seconds> s`; with many runs, that start
  takes longer. The other new indexes and checks lock their table while
  they read its rows, among them `run_files`, `artifacts`, `connections`
  and `api_keys`: with many rows there, upgrade at a quiet time. On Cloud
  Run and Azure Container Apps, the server's startup probe now allows 10
  minutes, so a first start has that long to run them.

- **On a runtime that served many tenants on 0.6.x, run
  `kindgi-runtime tenants repair --all` once after the upgrade,** with the
  server's database and OpenFGA settings (`KINDGI_OPENFGA_API_URL`, with
  its preshared key and auth). It puts back the runner roles 0.6.x may have
  dropped; `--dry-run` shows what it would put back and take away, and
  changes nothing
  ([After each upgrade: tenants repair](../../deploy/self-hosted/serve-many-tenants/#after-each-upgrade-tenants-repair)).
  Such a runtime no longer brings each tenant's authorization store up to
  the new model when it starts: it does so the first time it uses the
  store, and logs `authz: store brought up to the current model`. One it
  can't logs `authz: could not bring a store up to the current model` at
  WARN, goes on with the store's model, and tries again at a later use. A
  runtime serving one tenant still does it when it starts, and needs no
  repair.

- **Runs that waited on a deleted run end.** Within about a minute of the
  first start, each unfinished run that was part of a run whose record was
  deleted, by retention for example, fails with
  `Interrupted: a run it was part of was deleted, so nothing waits for it.`
  So runs that showed as running or waiting for a long time may change to
  failed.

- **Let the server reach access.kindgi.com.** The runtime now reports its
  usage at most once a day, with its license key, to
  `https://access.kindgi.com/v1/report`, through `HTTPS_PROXY` when that's
  set. A report that can't be sent never stops it, and it tries again
  within the hour. The answer can renew the key, which the runtime keeps in
  its database and runs on from then on. A key that doesn't report never
  does, and a server that can't reach Kindgi can ask for one
  ([What the runtime sends](../../deploy/self-hosted/what-the-runtime-sends/)).

- **With `KINDGI_SECRETS_BACKEND=secret-manager`, run tenant purges with
  the secret manager's settings.** `kindgi-runtime tenants purge` and
  `tenants repurge` now erase a tenant's secrets in the secret manager too,
  so they need `KINDGI_SECRETS_MANAGER` and that manager's settings.
  Without them, a purge of a tenant with secrets there is refused, and
  says how many and in which manager
  ([When an org, a project or a tenant goes](../../deploy/self-hosted/secret-manager/#when-an-org-a-project-or-a-tenant-goes)).

- **Once you set `KINDGI_ADMIN_EMAILS`, keep its line.** Nobody loses
  tenant admin at the upgrade itself, since no one is one by this setting
  before it. After that, a start without it, such as a redeploy that drops
  it from the runtime's environment, takes tenant admin from everyone the
  list made one, and they stay members. Tenant admins made in People or
  with `tenants make-admin` are never touched
  ([Tenant admins by email](../../deploy/people-and-keys/#tenant-admins-by-email)).

- **People removed before 0.7.0 keep the connections they own** until
  their removal is finished. Removing them again finishes it and changes
  nothing else: `kindgi people remove <user-id>`,
  `POST /v1/identity/users/{userId}/unregister`, or **Finish removing** on
  their page in the console, which shows while they still hold any.

- **In Python, Java and Scala, upgrade the client with the runtime, and
  build each pack once before you deploy it.** A client from before this
  release fails to read an HTTP tool whose `secretRef` names no env, or a
  page of tools that holds one; for the JVM client, see Known issues. Run
  `kindgi build` (or `kindgi dev`) on this CLI, so a flow the deploy would
  now refuse shows up as a file error first.

- **On Cloud Run, the upgrade's plan adds the license renewer's secret.**
  It makes one empty Secret Manager secret, `<name_prefix>-license-renewer`
  (or `license_renewer_secret`), which `kindgi license enroll` fills once,
  and gives the server `KINDGI_LICENSE_KEY_REF` and
  `KINDGI_LICENSE_RENEWER_REF`, so its expiry warning names the exact
  `kindgi license renew`. To renew on a schedule, set
  `license_renewal_schedule` after the upgrade, in an apply of its own:
  its job, schedule and alerts are more than the upgrade's plan check
  allows.

- **On Azure Container Apps with `license_renewal_schedule`, the expiring
  alert fires earlier.** It used to fire when the key had under 7 days
  left. It now fires inside the key's own warning window, the same line
  `kindgi license renew` warns with: from 30 days before the key expires
  for a key that sets no warning. The plan changes the alert in place.
